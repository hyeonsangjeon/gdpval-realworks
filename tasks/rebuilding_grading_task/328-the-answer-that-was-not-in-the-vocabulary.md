# 328 — 프롬프트 A/B를 샀고, 원인은 아직 안 갈렸다

**요약.** [`326`](./326-prompt-arm-prereg.md)이 사전등록한 실험을 120번 호출로 실제로
샀다. 얻은 것과 못 얻은 것을 순서대로 적는다.

* **소리는 확실히 갔다.** 이번엔 추정이 아니라 공급자가 센 숫자로 확인했다.
  120번 전부 오디오를 실었고, 공급자가 보고한 오디오 토큰이 **클립 길이 × 정확히
  10.00개**였다. 두 갈래가 같은 바이트를 들었다는 것도 확인했다 —
  `clips_with_more_than_one_digest`가 비어 있다. **실험은 유효하다.**
* **사전등록한 1차 지표는 "처치가 유의하게 나쁘다"로 나왔다** (p = 1.10 × 10⁻⁵).
* **그런데 그 숫자는 소리를 잰 게 아니다.** 처치 갈래는 답의 *형식*이 무너졌다.
  60번 중 43번이 JSON으로 안 읽혔고, 읽힌 17번은 `pass`/`fail`이 아니라
  `true`/`false`로 답했다. 채점기는 `pass`가 아닌 것을 전부 "아니다"로 센다.
* 그래서 관대하게 다시 채점하면 **처치가 오히려 나아 보이고**(정확도 66.7%,
  판별력 J = 0.29), 그때의 짝 비교는 **차이 없음**(p = 1.0)이다. 두 채점이 정반대다.

> **결론: 이번 실행은 프롬프트와 능력을 가르지 못했다.** 응답 어휘를 강제한 뒤
> 다시 사야 한다. 이것도 결과이고, 숨기면 그게 과잉 주장이다.

[`324`](./324-the-speech-it-heard-in-silence.md)의 수치는 **한 개도 안 고쳤다.**

## 3. 사전등록한 1차 지표의 답

326 §4가 실행 전에 고정한 대로, 같은 `(문항, 회차)`를 짝으로 묶어 **정확 이항
McNemar(양측)** 를 돌렸다. 60짝 전부 양쪽에 짝이 있었다.

| | 대조 `production` | 처치 `observation` |
|---|---:|---:|
| 시도 | 60 | 60 |
| 답한 호출 | 51 | **17** |
| **응답률** | **0.850** | **0.283** |
| 맞힌 호출 | 28 | 8 |
| **정확도(답한 것 기준)** | **54.90%** | **47.06%** |
| **판별력 J** | **0.0602** | **0.0** |

| 엇갈림 | 값 |
|---|---:|
| 대조만 맞음 | **21** |
| 처치만 맞음 | **1** |
| 둘 다 맞음 | 7 |
| 둘 다 틀림 | 31 |
| **정확 McNemar p** | **1.0967254638671875 × 10⁻⁵** |

사전등록 표의 넷째 줄이다.

> **처치가 유의하게 나쁘다 → 관찰 지시가 해가 됐다. 그것도 결과다.**

**처치 갈래는 문항을 골라 버려서 정확도를 올린 게 아니다.** 훨씬 많이 답을 못
냈고(0.283 대 0.850), 답한 것마저 더 낫지 않았다. 326 §4가 경계했던
"응답률 없이 정확도만 보면 개선처럼 보인다"는 함정은 이번엔 발생하지 않았다.

## 4. 그런데 이 p값은 소리에 대한 문장이 아니다

여기가 이 문서의 핵심이다. **왜 처치가 나빴는지**를 보면 이야기가 바뀐다.

### 못 답한 43번은 거절이 아니라 파싱 실패였다

| 갈래 | 못 답한 호출 | 기록된 사유 |
|---|---:|---|
| `production` | 9 | `provider_error:JSONDecodeError` 9건 |
| `observation` | 43 | `provider_error:JSONDecodeError` 43건 |

**전부 같은 사유 하나뿐이다.** 그리고 이 호출들은 사용량이 다 붙어 있고
(`usage_complete` 120/120) 출력 토큰도 썼다. **모델은 답을 했다.** 채점기가
그 답을 JSON으로 못 읽었을 뿐이다. 자리는 `core/perception/audio.py`의
`_parse_json_envelope`이고, 실패하면 그 문항은 판정 없이 끝난다.

326 §2는 "응답 봉투(JSON 형식)는 두 갈래가 같아서, 형식 차이로 응답률이 갈리지
않게 했다"고 적었다. **그 가정이 깨졌다.** 봉투 지시는 같았는데도 머리말이
출력 형식을 바꿨다.

### 답한 17번은 다른 낱말로 답했다

| 갈래 | 나온 `verdict` 문자열 |
|---|---|
| `production` | `fail` 41 · `pass` 9 · **`no` 1** · `judge_error` 9 |
| `observation` | **`true` 13 · `false` 2 · `refuse` 1 · `analyze_audio` 1** · `judge_error` 43 |

채점 규칙은 `said_pass = (verdict == "pass")` 한 줄이다
(`measure_audio_grading_accuracy.py`의 `classify`). 그래서 처치 갈래의 17번은
**하나도 `pass`가 아니었고, 전부 "기준이 성립하지 않는다"로 세어졌다.**

그러면 §3의 숫자가 왜 그 모양인지가 설명된다.

* 참인 문항에 답한 9번 → **전부 미탐지로 계산**, 정확도 **0.0**
* 거짓인 문항에 답한 8번 → 전부 맞은 것으로 계산, 정확도 **1.0**
* 그래서 J = 0 − 0 = **정확히 0.0**

**J가 0.0인 건 모델이 소리를 못 들어서가 아니라, 채점기가 이 갈래의 모든 답을
같은 쪽으로 접었기 때문이다.**

### 관대하게 다시 채점하면 부호가 뒤집힌다

`true`를 `pass`로, `false`를 `fail`로 읽고(`refuse`·`analyze_audio`는 답이 아닌
것으로 버림) 다시 세면 이렇다. **이건 사후 분석이다. 사전등록에 없다.**

| | 사전등록 채점 | 사후 관대 채점 |
|---|---:|---:|
| 처치가 쓸 수 있는 답 | 17 | 15 |
| 처치 정확도 | 47.06% | **66.67%** |
| 처치 J | 0.0 | **0.2857** (P(pass\|참) 8/8, P(pass\|거짓) 5/7) |
| 짝 비교에 남는 짝 | 60 | 15 |
| 대조만 맞음 : 처치만 맞음 | 21 : 1 | **4 : 5** |
| **McNemar p** | **1.10 × 10⁻⁵** | **1.0** |

관대 채점의 J = 0.2857도 **유의하지 않다** (2×2 정확검정 p = 0.20, n = 15).
그러니 "관대하게 보면 처치가 낫다"고 말할 근거도 없다. 말할 수 있는 건 이것뿐이다.

> **채점 규칙 하나를 바꿨더니 "유의하게 나쁘다"가 "차이 없다"로 바뀐다.
> 두 결과의 차이는 전부 응답 형식에서 오고, 소리에서 오지 않는다.**

### 그래서 이번 실행이 실제로 답한 질문

| 질문 | 답 |
|---|---|
| 오디오가 요청에 실렸나 | **실렸다.** 120/120, 초당 10.00토큰 |
| 두 갈래가 같은 바이트를 들었나 | **들었다.** 클립당 해시 1개 |
| 운영 프롬프트에 이 머리말을 얹으면 채점이 되나 | **안 된다.** 60번 중 43번이 판정 없이 끝난다 |
| **관찰 지시가 듣는 능력을 바꿨나** | **모른다.** 이 실행으로는 못 가른다 |

326이 가르려던 두 설명 — **프롬프트**와 **능력** — 은 **아직 안 갈렸다.**

## 5. 대조 갈래는 324를 독립적으로 재현했다

처치 쪽이 흔들려도 대조 갈래 60번은 그대로 쓸 수 있다. 324와 다른 날, 다른
실행, 새로 산 60번이다. 결과는 같은 방향이다.

| 지표 | 값 |
|---|---|
| 정확도(답한 51번 기준) | 54.90% (28/51) |
| 응답률 | 0.850 |
| 참인 문항 정확도 | **20.83%** (5/24) — 미탐지율 0.792 |
| 거짓인 문항 정확도 | 85.19% (23/27) — 오탐지율 0.148 |
| **판별력 J (호출별)** | **0.0602** |
| 판별력 J (문항 다수결) | **−0.1111** |
| 짝 안 순열검정 | 10짝 · 1024가지 · **p = 0.2969** (가능한 최소 p = 0.00098) |
| 반복 3번이 완전히 같았던 문항 | 20개 중 **13개** (다수결 안 나온 문항 2개) |

**참인 문항의 정확도가 20.8%라는 건 "거의 다 아니라고 답했다"는 뜻이다.**
거짓인 문항에서 85%가 나온 건 잘 들어서가 아니라 같은 "아니다"가 우연히
맞아떨어진 것이고, 그래서 J가 0에 붙는다. 324의 그림이 그대로 다시 나왔다.

확신도는 정답·오답을 가리지 않는다.

| 결과 | 평균 확신도 |
|---|---:|
| 맞힌 호출 | 0.897 |
| 미탐지(참을 아니라 함) | 0.907 |
| 오탐지(거짓을 맞다 함) | 0.913 |

**틀렸을 때가 살짝 더 자신 있다.** 이 확신도 값으로는 어떤 답이 믿을 만한지
고를 수 없다.

대조 갈래에서도 `no`가 한 번 나왔다. **어휘를 벗어나는 일은 처치 갈래만의
문제가 아니다.** 다만 60번에 1번(1.7%)과 60번에 17번(28%)은 규모가 다르다.

## 6. 이번에 드러난 채점기 쪽 문제 하나

`core/perception/audio.py`는 모델이 돌려준 값을 이렇게 받는다.

```python
verdict=str(payload.get("verdict", "fail")),
```

**어휘 검사가 없다.** `true`든 `refuse`든 `analyze_audio`든 그대로 통과하고,
없으면 조용히 `"fail"`이 된다. 같은 저장소의 본 판정자는 반대다 —
`tool_calling_judge._validated_final_envelope`는 `{pass, partial, fail}` 밖의
값을 보면 봉투 전체를 **거절**한다.

즉 **본 판정자에는 있는 검사가 오디오 하위 판정자에는 없다.**

이 문서는 그 사실만 적는다. **이번 진단 PR에서 운영 채점기는 한 줄도 안 고친다**
(카드 조건). 하위 판정자가 어휘 밖 문자열을 돌려줬을 때 본 판정자가 그걸
어떻게 읽는지는 이번 실행이 답하지 않았고, 그건 별도로 재야 한다. 다음 순서는
§8에 적었다.

---

## 7. 실행이 빨간 이유 — 문항 2개는 한 번도 안 재졌다

작업은 exit code 2로 끝났다. 주석에 찍힌 문장은 이것이다.

```
::error::no verdict was reached for: presence_false, timing_true
```

이 두 문항은 **양쪽 갈래 · 3회차 전부, 6번 다 `judge_error`** 였다. 한 번도
판정이 안 나왔다는 뜻이다.

| 문항 | 6번의 결과 |
|---|---|
| `presence_false` | `judge_error` × 6 |
| `timing_true` | `judge_error` × 6 |

**이 빨간불은 고장이 아니라 신호다.** 20개 중 2개를 못 쟀는데 초록으로 끝났다면
그게 거짓말이다. 방어는 의도대로 동작했고 **약화하지 않는다.** 산출물과 보고서는
정상적으로 다 나왔으므로(요약 단계와 업로드는 실패해도 돌게 만들어 뒀다) 위
숫자들은 전부 살아 있다.

다만 **§3·§5의 분모는 20개가 아니라 18개 문항에서 나온 것**이라는 뜻이기도 하다.
대조 갈래에서 `presence`와 `timing` 계열의 응답률은 각각 0.5로, 다른 계열보다
눈에 띄게 낮다.

## 8. 남은 한계

1. **원인은 안 갈렸다.** 이 문서가 지운 건 "소리가 안 갔다"뿐이고, 그건 325가
   이미 지운 것을 더 강한 증거로 다시 지운 것이다. **프롬프트와 능력은 그대로
   남아 있다.**
2. **처치 머리말은 다섯 가지를 한꺼번에 바꾼 묶음이다**(326 §2). 어느 하나가
   형식을 무너뜨렸는지 이 설계로는 못 가른다. 특히 다섯째("못 정하겠으면
   `judge_error`를 내라")가 형식 이탈을 유도했을 수 있지만 **확인 안 됐다.**
3. **여전히 합성 음악이다.** 말소리 절반은 이번에도 안 했다.
   326 §7의 사유가 그대로 남아 있다 — **낱말 알아듣기는 정답의 외부 근거가 아직
   없고, 그걸 세우려면 바이트가 고정된 오프라인 TTS 바이너리를 먼저 박아야 한다.**
   녹음된 개인정보나 실제 사람 목소리 복제는 쓰지 않는다.
4. **처치가 나쁘다고 나온 것이 "능력이 없다"의 증거가 아니다.** 반대 방향도
   마찬가지다. 관대 채점에서 J = 0.29가 나왔다고 "들을 줄 안다"고 말할 수 없다
   (p = 0.20, n = 15).
5. **9개 클립 · 20문항 · 모델 하나 · 3회 반복이라는 크기는 그대로다.**
   326 §4가 계산해 둔 대로 이 설계는 작은 차이를 못 본다.
6. **185과제 실행의 오디오 채점 31건은 이 실행과 무관하고 손대지 않았다.**
   점수는 하나도 안 바뀌었다.

## 9. 다시 세는 법

값 없이, 저장소에 있는 파일만으로.

```bash
cd tasks/rebuilding_grading_task
python - <<'PY'
import json, collections
from math import comb
d = json.load(open("328-audio-accuracy-measured.json"))
holds = {c["claim_id"]: c["holds"] for c in d["claims"]}
dur = {c["clip_id"]: c["duration_s"] for c in d["clips"]}

print("[2] 오디오 토큰 / 초")
seen = {}
for c in d["calls"]:
    seen[c["clip_id"]] = c["wire"]["audio_tokens"] / dur[c["clip_id"]]
print("   ", sorted(set(round(v, 2) for v in seen.values())))

print("[2] 갈래별 토큰-길이")
def fit(xs, ys):
    n = len(xs); mx = sum(xs)/n; my = sum(ys)/n
    sxy = sum((a-mx)*(b-my) for a, b in zip(xs, ys))
    sxx = sum((a-mx)**2 for a in xs); syy = sum((b-my)**2 for b in ys)
    s = sxy/sxx
    return sxy/(sxx*syy)**0.5, s, my - s*mx
for arm in ("production", "observation", None):
    sub = [c for c in d["calls"] if arm is None or c["arm"] == arm]
    r, s, i = fit([dur[c["clip_id"]] for c in sub], [c["input_tokens"] for c in sub])
    print("    %-12s n=%3d r=%.4f slope=%.2f intercept=%.1f"
          % (arm or "BOTH", len(sub), r, s, i))

print("[4] 갈래별 verdict 문자열")
for arm in ("production", "observation"):
    print("   ", arm, dict(collections.Counter(
        c["verdict"] for c in d["calls"] if c["arm"] == arm)))

print("[4] 사후 관대 재채점")
def remap(c):
    v = c["verdict"]
    return ({"true": "pass", "false": "fail"}.get(v) if c["arm"] == "observation"
            else (v if v in ("pass", "fail", "partial") else None))
byk = collections.defaultdict(dict)
for c in d["calls"]:
    byk[(c["claim_id"], c["repeat"])][c["arm"]] = c
pairs = [v for v in byk.values()
         if remap(v["production"]) and remap(v["observation"])]
ok = lambda c: (remap(c) == "pass") == holds[c["claim_id"]]
B = sum(1 for v in pairs if ok(v["observation"]) and not ok(v["production"]))
C = sum(1 for v in pairs if ok(v["production"]) and not ok(v["observation"]))
n = B + C
p = None if n == 0 else min(1.0, 2*sum(comb(n, i) for i in range(min(B, C)+1))/2**n)
print("    짝=%d  대조만=%d  처치만=%d  McNemar p=%s" % (len(pairs), C, B, p))

print("[7] 한 번도 안 재진 문항")
per = collections.defaultdict(list)
for c in d["calls"]:
    per[c["claim_id"]].append(c["verdict"])
print("   ", sorted(k for k, v in per.items()
                    if all(x == "judge_error" for x in v)))
PY
```
