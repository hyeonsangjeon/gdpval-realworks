# 312 · 네 번째 소리 smoke — **통과**, 그리고 점수가 왜 내려갔나

`311`은 "소리가 실제로 들리는가"에 답했다. 들린다.

이번 문서의 질문은 다르다. **같은 파일을 두 번 채점했는데 점수가 6점 내려갔다.**
32.56% → 26.37%. 그 사이에 코드는 거의 바뀌지 않았다.

답부터 쓴다. **고장이 아니다.** 이 채점기는 원래 그만큼 흔들린다.
다만 **소리 항목은 다른 항목보다 네 배 더 흔들린다.** 그게 이번에 새로 알아낸 것이다.

## 2. 먼저, 반드시 통과해야 하는 네 가지

사장님이 정하신 실패 조건은 네 개였다. 하나라도 걸리면 성공이라 부르지 말 것.

| 조건 | 결과 |
|---|---|
| 소리 창구가 실제로 불렸는가 | **불렸다.** `gpt-audio-1.5`로 17번, 전부 `settled` |
| 다른 모델로 몰래 갈아탔는가 (fallback) | **0건.** 부른 모델과 답한 모델이 17번 모두 같다 |
| 결과 파일이 반쪽인가 (partial) | **아니다.** 2개 과제 전부 채점, 실패 과제 0 |
| 신분이 어긋났는가 (identity) | **정확히 일치.** 파일 안의 지문 = 파일 이름의 지문 = 계산한 지문 |

**네 개 다 통과다.**

비용은 이번에도 **금액을 적지 않았다.** `gpt-5.6-sol`과 `gpt-audio-1.5`가
가격표에 없기 때문이다. `$0`이 아니라 **"값 모름(partial)"** 으로 적혀 있다.

| | |
|---|---|
| 총 호출 | 233건 (채점 216 · 소리 17) |
| 토큰 | 들여보낸 560,885 · 받은 45,505 · 재사용 477,804 |
| 기록된 금액 | `null` — 가격표에 없는 모델이라 계산 불가 |
| 값 모르는 모델 | `gpt-5.6-sol`, `gpt-audio-1.5` |

## 3. 그런데 점수가 내려갔다

| | 3차 (`322a6c10`) | **4차 (이번, `4992ad4f`)** |
|---|---|---|
| `e222075d` | 11.0 / 58 = 18.97% | **10.0 / 60 = 16.67%** |
| `75401f7c` | 25.85 / 56 = 46.16% | **20.2 / 56 = 36.07%** |
| 평균 | 32.56% | **26.37%** |

한 번에 6점이 빠졌다. 이걸 설명하지 못하면 185개를 살 수 없다.

### 먼저 범인 후보를 지웠다

3차와 4차 사이에 들어온 변경은 셋뿐이다.

- **#306** (그림 예산 고침) — **범인이 아니다.** 두 실행 모두 `visual_budget_fallback`이
  비어 있고, 73개 항목 전부 `visual_budget_downgraded: false`다.
  **#306이 고친 길로는 아예 들어가지도 않았다.**
- **#308** (설정 파일의 설명 문구 한 줄) — 동작 없음.
- **#310** (지문 잠금장치) — `batch-runner` 바깥이라 채점에 닿지 않는다.

코드가 범인이 아니면 남는 건 하나다. **채점하는 모델이 마음을 바꿨다.**

## 4. 이 채점기는 원래 얼마나 흔들리나

여기서 처음으로 제대로 재봤다. 30개 과제를 **똑같은 지문으로 세 번** 채점한
기록이 이미 있었다 (`_repeats/run-002`, `run-003`, 그리고 원본).
1,433개 항목을 세 쌍으로 비교한 결과다.

| 비교 | 판정이 달라진 항목 |
|---|---|
| 원본 vs run-002 | 153 / 1,433 = **10.7%** |
| 원본 vs run-003 | 144 / 1,433 = **10.0%** |
| run-002 vs run-003 | 153 / 1,433 = **10.7%** |

**같은 파일, 같은 채점기, 같은 설정인데 열에 하나는 매번 다르게 나온다.**
이건 이번에 생긴 문제가 아니라 이 채점기의 원래 성질이고, 이미 받아들인
174개 증거도 똑같이 이 성질을 갖고 있다.

이번 smoke는 73개 중 10개가 달라졌다 — **13.7%.** 위의 10%와 같은 범위다.

## 5. 그런데 소리만 유독 심하다

같은 실행 안에서 종류별로 나눠 보면 이야기가 달라진다.

| 종류 | 달라진 항목 |
|---|---|
| 글자 | 2 / 48 = **4%** |
| 그림 | 0 / 4 = **0%** |
| **소리** | **8 / 21 = 38%** |

**소리는 글자의 아홉 배, 전체 평균의 네 배로 흔들린다.**
그리고 8개 중 7개가 **점수가 깎이는 쪽**으로 움직였다.

### 왜인지는 증거 문장을 나란히 놓으면 바로 보인다

같은 파일, 같은 30초다.

> **"배경 음악이 30초 지점에서 정확히 끝난다"** (확신 0.95)
> **"30초 클립 전체에 배경 음악이 전혀 들리지 않는다"** (확신 0.96)

> **"드럼과 기타 리프가 곡 전체에 걸쳐 들린다"** (확신 0.90)
> **"폭발음과 총성뿐이고 음악 트랙은 구분되지 않는다"** (확신 0.82)

둘 다 자신 있게 말하는데 **정반대**다.
이건 "애매한 걸 다르게 판단했다"가 아니라, **소리 창구가 매번 다른 내용을 들려주고 있다**는 뜻이다.

확인한 것들:

- 두 실행 모두 **같은 파일**을 봤다 — 21개 소리 항목 전부 `selected_paths` 동일.
- 판정이 뒤집힌 항목은 **양쪽 다 실제로 들었다** (`perception_call_count: 1`).
  호출이 빠져서 생긴 일이 아니다.
- 호출이 19 → 17로 준 2건은 **양쪽 다 이미 실패**였던 항목이라 점수와 무관하다.

## 6. 그래서 이번 결과는 나쁜 건가

아니다. **기준선과 비교하면 오히려 올라가 있다.**

| 과제 | 174개 때 (받아들인 증거) | 3차 | **4차 (이번)** |
|---|---|---|---|
| `e222075d` | 10.3 / 60 = 16.17% | 18.97% | **16.67%** |
| `75401f7c` | 18.0 / 56 = 26.34% | 46.16% | **36.07%** |

두 과제 모두 **174개 때보다 높다.** 소리를 듣게 만든 효과는 그대로 살아 있다.
3차가 유난히 잘 나온 쪽이었고, 4차는 같은 분포에서 낮게 뽑힌 것이다.

## 7. 이 문제의 크기

**185개 중 딱 2개다.**

이 corpus에서 영상 파일이 답안인 과제는 `e222075d`와 `75401f7c` 둘뿐이다
(`304-full-gold-corpus.md`). 30개 cohort에는 소리 항목이 **하나도 없다** —
1,433개가 전부 글자·서식·그림이다.

즉 이 흔들림은 **전체의 1%에만 닿는다.** 나머지 183개는 글자 항목의 10% 기준선을
그대로 따른다.

## 8. 판정

**통과다.** 그리고 185개 전체 채점을 **출발시켰다.**

이유는 이렇다. 실패 조건 네 개는 전부 통과했고, 점수 변화는 **설명됐다** —
이 채점기가 원래 갖고 있던 10% 흔들림에 소리 항목의 추가 흔들림이 얹힌 것이다.
여기서 멈추는 것은 **이미 받아들인 174개 증거에도 똑같이 있는 성질**을 이유로
새 관문을 만드는 일이 된다.

다만 **반드시 같이 적어두어야 할 한계**가 있다:

> **`e222075d`와 `75401f7c`의 소리 항목 점수는 재현되지 않는다.**
> 같은 설정으로 다시 채점하면 이 두 과제의 소리 항목 중 약 40%는 다른 판정이 나온다.
> 이 두 과제의 개별 점수는 **한 번 뽑은 표본**으로 읽어야 하고, 확정값으로 인용하면 안 된다.

이건 다음에 고칠 문제로 남긴다 (`probe_audio`가 같은 입력에 같은 답을 주도록
만드는 일 — 30초 자르는 구간이 고정인지부터 확인해야 한다).
