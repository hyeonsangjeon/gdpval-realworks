# 323 — 읽을 수 있는 형제, 결국 한 건도 막지 않았다

**요약.** [`322`](./322-the-probe-that-never-learned-video.md) §9이 "고치지 않고 시험으로만
박아둔" 한계가 하나 있다. **읽을 수 있는 파일이 옆에 같이 선택되면 시각 채점으로 가는 문이
안 열린다**는 것이다. 그게 실제로 몇 건을 막았는지 **전수로 재봤다. 0건이다.**

재는 김에 **`322` 자신의 숫자가 틀린 것도 찾았다.** `47`이 아니라 `48`이다.
`322`가 §10에 적어둔 세는 방법을 `322`가 스스로 안 지켰다. 그 이야기는 §7에 있다.

**이 문서는 코드를 하나도 고치지 않는다.** 채점기 지문 14개 전부 그대로다(§8).
모델 호출 0회, 비용 **$0**.

---

## 1. 무엇이 한계였나 — 문에는 조건이 셋이다

단어에 "차트"·"색깔" 같은 시각 신호가 없는 기준이 눈으로 보는 채점에 닿는 길은
`resolve_runtime_routing`의 **승격 문** 하나뿐이다(`core/grader_routing.py:375`).
그 문은 조건 **세 개를 전부** 만족해야 열린다.

| | 조건 | 이번 한계와의 관계 |
|---|---|---|
| **가** | 고른 파일 중 **글자가 안 나오는 게 있다** | 섞인 묶음도 **통과시킨다** |
| **나** | 기준이 글자·서식 분류다 | 관계없음 |
| **다** | 고른 파일의 확장자가 **전부** 그림으로 바꿀 수 있다 | **여기서 막힌다** |

가) 조건은 이미 관대하다. `some_selected_path_lacks_text`라는 신호가 있는 이유가
바로 "일부만 안 읽히는 묶음"을 살리기 위해서다. 그런데 다) 조건은 `issubset`이라
**하나라도 `.txt`·`.py`가 끼면 묶음 전체가 글자 채점에 남는다.**

`322`는 이걸 발견하고도 안 고쳤다. 대신 시험 한 줄로 박아뒀다
(`test_a_video_beside_an_unrenderable_sibling_stays_on_the_reader`).
**안 고친 판단이 옳았는지를 확인하는 게 이 문서다.**

## 2. 세는 방법 — `322` §10이 정한 대로

`322`는 마지막에 이렇게 적었다.

> **딱지가 붙은 항목만 세면 딱지가 안 붙는 고장은 못 찾는다.**
> "채점기가 실패했다고 말한 항목"이 아니라 **"판정자가 손에 뭘 들고 있었나"**를 봐야 한다.

이번 고장에도 딱지가 안 붙는다. 문이 안 열린 항목은 그냥 글자 채점으로 정상 처리된다.
그래서 **"막혔다고 기록된 항목"을 찾는 게 아니라, 올라갈 수 있었던 항목을 전부 세고
그중 몇 개가 다) 조건에서 거절됐는지**를 봤다.

두 가지를 따로 쟀다.

* **가) 조건까지 통과한 항목 전수** — gold 185 채점 결과의 모든 항목에 오늘의 탐침을
  다시 태운다. 파일을 직접 열어야 해서 **CI에서는 못 돈다**(§3).
* **섞인 묶음이 실제로 발행된 자리 전수** — 커밋된 채점 결과 99개를 훑는다.
  파일이 필요 없으므로 **CI에서 돈다**(§4).

## 3. gold 185 전수 — 다) 조건이 막은 항목 0건

```
gold-185 text/formatting items with selected paths : 8184
  text signal PERMITS escalation                   : 48   (across 2 tasks)
    -> every suffix renderable, gate FIRES          : 48
    -> mixed suffixes, BLOCKED by issubset clause   : 0   (across 0 tasks)

files the probe could not answer for: 5 -> ['DEJA VU  STEMS .zip',
  'PrivateCrypMixV2.zip', 'TOASTY_REVA_STEP_FILES.zip',
  'contact form serverless backend.zip', 'screen_reader_status_message.zip']
tasks with a selected file missing on disk: {}
```

읽는 법.

* **8,184** — gold 185에서 글자·서식으로 분류되고 파일이 선택된 항목 전부. 모집단이다.
* **48** — 그중 가) 조건을 통과한 것. 즉 "글자가 안 나오는 파일이 들어 있다"가 참인 항목.
* **48** — 그 48건이 전부 다) 조건도 통과해서 **문이 실제로 열린다.**
* **0** — 다) 조건에 걸려 막힌 항목. **한 건도 없다.** 걸린 과제 수도 0이다.
* **마지막 줄이 중요하다.** 선택된 파일이 디스크에 하나도 안 빠졌다. 파일을 못 찾아서
  0이 나온 게 아니라는 뜻이다. 이 줄이 없으면 이 측정은 §7이 고치는 것과 **같은 종류의
  거짓말**이 된다 — 질문이 못 찾은 것을 데이터에 없다고 말하는 것.

**교차 검증.** 저 `48`은 `322`가 센 "영상을 못 본 채 채점된 항목" 48건과 같은 수다.
완전히 다른 두 계산이 같은 답을 냈다 — `322`는 채점 결과의 판정 내역을 셌고, 여기서는
파일을 직접 열어 라우팅을 다시 돌렸다. (`322`가 처음 적은 47이 틀렸다는 것도
이 대조에서 나왔다. §7.)

**이 블록은 CI에서 재현되지 않는다.** 제출물 파일이 필요한데
`data/gdpval-local/`은 `.gitignore:343`에서 제외된다. 그래서 시험이 아니라 **문서에**
적는다. 낸 명령은 이렇다.

```bash
# 제출물 스냅샷을 받아둔 폴더를 두 번째 인자로 준다
python gate_scan_323.py <repo> <deliverable_snapshot>
```

```python
for item in items:                      # gold 185 채점 결과의 모든 항목
    if routing_modality not in ("text", "formatting"): continue
    if not selected_paths:               continue
    scanned += 1

    answers  = [has_extractable_text(f) for f in selected_paths]   # 파일별 1회 캐시
    lacking  = [f for f, a in zip(selected_paths, answers) if a is False]
    have_text = any(answers) if all(a is not None for a in answers) else None

    if not (have_text is False or lacking):   # 가) 조건
        continue
    permits += 1

    if suffixes.issubset(GRADER_VISUAL_RENDER_EXTENSIONS):        # 다) 조건
        fires += (resolve_runtime_routing(...).modality is VISUAL)
    else:
        blocked += 1                                              # ← 이게 0이다
```

탐침 결과를 **파일 단위로 캐시**한다. 같은 제출물을 수십 개 항목이 함께 고르기 때문에
항목마다 열면 15분, 파일마다 열면 **14초**다. 답은 같다 — 탐침은 파일만 보는 함수다.

## 4. 발행된 채점 전체 — 섞인 묶음은 세 과제뿐

이쪽은 파일이 필요 없어서 시험으로 박았다
(`tests/test_a_readable_sibling_keeps_a_bundle_on_the_text_route.py`).
커밋된 채점 결과 **99개**를 전부 열어, 글자·서식 항목 중 **그림으로 바꿀 수 있는 파일과
없는 파일이 한 묶음에 같이 선택된** 것을 센다.

| 과제 | 묶음 모양 | 결과 파일 | 항목 |
|---|---|---:|---:|
| `46fc494e` (기계공학, gold 185) | `.pdf` + `.py` | 4 | 280 |
| `58ac1cc5` (프로젝트 관리, 220 실행) | `.docx`·`.pdf` + `.txt` | 6 | 234 |
| `bf68f2ad` (생산 감독, 220 실행) | `.xlsx` + `.txt` | 6 | 208 |
| | | **12** | **722** |

훑은 모집단은 글자·서식 항목 **95,699개**. 섞인 묶음은 그중 722개, **0.75%**다.

**그리고 722개 전부 가) 조건에서 이미 막힌다.** 묶음 안의 그림 파일이 글자를 내놓기
때문이다 — `.xlsx`도 `.docx`도 `.pdf`도 판독기가 글자를 뽑아낸다. 글자가 나오면
`selected_paths_have_text`가 참이 되고, 문은 **다) 조건에 닿기도 전에** 닫힌다.
`.txt` 형제는 발언권이 없다.

말로만 두지 않고 **판정자 근거 문자열에서 확인**했다. 판독기는 이진 파일에서 뽑은
글자에 출처를 찍어둔다.

| 과제 | 근거에 남은 자국 |
|---|---|
| `bf68f2ad` | `"kind": "xlsx"` — 6건 |
| `58ac1cc5` | `"kind": "docx"` 4건 · `[Page ` 2건 |
| `46fc494e` | **하나도 없다** — 280건 전부 자국 0 |

**마지막 줄은 숨기지 않고 적는다.** `46fc494e`의 280건에는 이진 파일에서 글자를 뽑았다는
자국이 **한 건도 없다.** 근거 문자열은 파이썬 소스 조각이거나 평범한 산문이고, 어느
쪽도 `.pdf`를 읽었다는 증거가 못 된다. 그 `.pdf`에서 글자가 나온다는 것은 파일을 직접
열어 확인했고, 그건 CI에서 재현이 안 된다. 그래서 이 과제에 대해서는 **다른 것을
증거로 삼았다.** §5를 본다.

## 5. 왜 안 고치는가 — 그리고 단어 경로는 이미 이 묶음을 처리한다

**첫째, 재어보니 얻을 게 0이다.** 발행된 어떤 점수도 이 구멍 때문에 달라지지 않았다.

**둘째, 이 문을 넓히는 일은 예전에 한 번 크게 틀린 적이 있다.** PR #303이 고친 결함이
바로 그것이다(`311` §9).

> 파일 하나가 안 읽혀서 항목을 그림 경로로 올렸는데, 올린 다음 **묶음 전체**를 그렸다.
> 과제 `43dc9778`은 항목 67개가 각각 파일 2개를 요구해 **134장**이 필요했고,
> 과제당 그림 예산은 **72장**이다. 예산을 넘겨 **67개 항목 전부가 점수에서 빠졌고,
> 그 과제는 87.36%에서 0.00%가 됐다.**

승격은 공짜가 아니다. 올라간 항목은 그림 예산을 쓴다. **얻는 게 0인데 예산을 건드리는
수정**은 위 사고와 정확히 같은 모양이다.

**셋째 — 그리고 이게 가장 재미있는 부분 — 단어가 있는 기준은 이 묶음을 이미 잘 처리한다.**
`46fc494e`의 `.pdf` + `.py` 묶음에서, 시각 단어를 가진 기준들은 **`.pdf`만 그리고 `.py`는
조용히 건너뛰었다.** 채점 결과에 그대로 남아 있다.

```
visual_provenance:  Material analysis Report.pdf   (source_kind: pdf)
그린 파일 집합:      {"Material analysis Report.pdf"}   ← .py 없음
```

즉 **묶음 자체는 아무 문제 없이 그려진다.** 거절하는 건 승격 문의 다) 조건뿐이고,
단어 경로는 그런 요구를 애초에 하지 않는다. 이게 `46fc494e`에 대한 증거이자,
"고칠 거면 다) 조건을 느슨하게 하는 게 아니라 **왜 두 경로가 서로 다른 요구를 하는지**부터
정리해야 한다"는 뜻이기도 하다. **지금 할 일은 아니다.**

## 6. 이 `0`이 깨질 수 있는 자리

지금 0이라고 영원히 0은 아니다. 깨질 조건을 적어둔다.

* **`.zip` 5개.** 탐침이 `모름`으로 답하는 유일한 확장자다(§3 마지막 줄). `모름`은
  아무것도 안 바꾸므로 지금은 문에 닿지도 않는다. 언젠가 압축 안을 들여다보게 되면
  이 5개가 **처음으로 다) 조건을 만나는 후보**가 된다.
* **새 채점 결과.** §4의 시험은 과제 세 개와 건수를 **정확히** 못 박아 뒀다.
  네 번째 과제가 생기면 시험이 빨개진다. **그건 결함이 아니라 다시 재라는 신호다** —
  시험 실패 메시지가 그렇게 적혀 있다.
* **선택기가 고르는 파일이 바뀌면.** 722건은 "지금 선택기가 이렇게 고른다"에 달려 있다.

## 7. 세는 김에 찾은 것 — `322`의 `47`은 `48`이다

`322`는 영상을 못 본 채 채점된 항목을 **47건**이라고 적었다. **48건이다.**

```
fail 38 + pass 9 = 47          ← 322가 적은 방식
fail 38 + pass 9 + partial 1 = 48   ← 실제
```

총계를 세지 않고 **판정 종류를 둘만 나열해서 더했다.** 이 집합에 `partial`이 하나
있는데 그 줄이 표에 없었다. **없는 줄은 틀린 줄보다 찾기 어렵다** — 남은 47건이
전부 `pass` 아니면 `fail`이라 두 종류만 더한 합은 자기들끼리 아귀가 맞았고,
그래서 검토·CI·병합을 전부 통과했다.

빠진 1건은 `75401f7c`의 **"Overall formatting and style of the deliverable"**,
5점 만점에 3.0점. 왜 빠뜨렸는지가 진짜 이야기다. `322` §4에 이렇게 적혀 있었다.

> ~~이 1건은 지금도 시각으로 분류되므로 위 47건에 안 들어간다.~~

`000-OVERVIEW.md`에는 **글자 그대로 이름이 같은 항목**을 `data_flow.txt`와
`MIG_Welding_Catch_Up_Summary.txt`에서 점수 제외한 것이 옳다는 판단이 적혀 있다.
순수 텍스트 파일에는 볼 모양이 없으니 맞는 판단이다. **그 제외를 이름만 보고
다른 과제로 가져왔다.** `75401f7c`가 낸 것은 `.txt`가 아니라 영상이다. 볼 모양이 있다.

**돈이 걸린 숫자는 안 움직인다.** 61점·−90점·18점 그대로. 늘어나는 것은 그 항목의
**아직 판정되지 않은 2점**뿐이다.

`322`가 "이 48건에서 가장 큰 양수 항목"이라고 적을 뻔한 것도 같이 바로잡았다.
가장 큰 것은 이 5점짜리가 아니라 **15점짜리** — `e222075d`의 *"모든 영상 소재를 무료
라이선스 플랫폼에서 가져왔다"* 이고 `fail`로 0점 처리됐다. 다만 이 항목은 **12칸 판으로도
답이 안 나온다.** 사진 열두 장으로 소재의 출처를 증명할 수는 없다.

**고친 곳:** `322`(머리말 + §1 표 + §4 + §11 신설), `318` §1, `000-OVERVIEW.md`,
그리고 `test_a_video_criterion_must_not_be_answered_by_reading.py`의 설명문.
마지막 것이 이 사고의 뿌리다 — **`322`는 47을 열 군데에 적었지만 그 열 군데를 읽는
시험은 하나도 없었다.**
