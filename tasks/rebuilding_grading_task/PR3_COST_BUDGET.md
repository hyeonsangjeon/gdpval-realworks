## 1. 한 줄 요약

302의 합격 기준은 **`per-run cost < $50`** 이다.
실제로 도는 파이프라인은 **$411.80 ~ $980.84** 를 쓴다. **8.2배에서 19.6배 초과다.**

그리고 302가 초과 시 처방으로 적어 둔 **"vision/audio cap 강화 / routing pattern
좁히기"** 는 이 초과를 고칠 수 없다. 그 처방이 닿는 지각(perception) 호출은
**청구서의 1.85% ~ 3.49%** 다. 전부 없애도 96.5% 이상이 남는다.

| | 302가 가정한 것 | 실제 |
|---|---|---|
| 판정 모델 | `gpt-5.4`, reasoning **medium** | `gpt-5.6-sol`, reasoning **max** |
| vision 상한 | "per task cap **5**" | `call_cap_per_task: **112**` (audio 32) |

| 실행당 비용 | **$52.1** (선형 외삽) | **$411.80 ~ $980.84** |

**기준이 파이프라인을 따라가지 못한 것이지, 파이프라인이 기준을 어긴 것이 아니다.**
`$50`은 2026-07-26에 사라진 설정에 붙어 있던 상수다.

## 4. $52.1은 어디서 왔나 — 3과제 표본은 표본이 아니었다

`PR3_SMOKE_FINDINGS.md`의 근거 두 줄은 이렇다.

```
$0.71 / 3 tasks = $0.237 per task average
220-task full extrapolation = $52.1
```

**그 $0.71을 커밋된 결과에서 다시 만들 수 없다.** 문서가 어떤 요율을 썼는지 적지 않았고,
그 실행의 토큰(입력 398,629 · 출력 43,359)을 `gpt-5.4`의 공표 미터 중
**가장 싼 것**(`batch_global`)에 넣어도 $0.8235, 표준 요율(`standard_global`)이면
$1.6470이다. **어느 쪽도 $0.71이 아니다.**

같은 문서가 인용한 과제별 숫자는 **정확히 재현된다** — `0419f1c3` 49호출 211,533토큰,
`dfb4e0cd` 165,882토큰. 즉 **데이터가 아니라 환산과 외삽이 문제였다.**
(문서의 "94% input"도 실제로는 90.2%다.)

### 4.1 같은 설정으로 220과제를 이미 돌렸고, 아무도 값을 안 매겼다

`exp003_..._judge_gpt-5_4__rubric_v2_tools.json` — 220과제, 215개 채점,
입력 107,844,571 · 출력 4,652,556 · 8,904 호출, `estimated_cost_usd: **0.0**`.

schema 1.0에는 캐시 토큰 칸이 없어 점이 아니라 범위만 나온다:
`standard_global`에서 **$96.75(전부 캐시) ~ $339.40(전부 미캐시)**.

**한 가지 규칙으로 양쪽을 재면** — 둘 다 `standard_global` 전부-미캐시로 —
비교가 정직해진다.

| | 과제당 | 220과제 환산 |
|---|---|---|
| 3과제 smoke | $0.5490 | **$120.78** |
| 220과제 실주행 | $1.5427 | **$339.40** (실측) |

**N=3은 과제당 비용을 2.81배 낮게 봤다.** 기록된 $52.1은 자기 토큰만 놓고 봐도
2.3배 낮았고, 그 위에 외삽 오차가 또 얹혔다.

이유는 3.2절에 있다. 비용 분포가 심하게 치우쳐 있어서 **평균이 표본 3개 안에 없다.**
smoke 문서 자신이 "heavy-tailed"라고 적었지만, 그때는 그것이 projection을 **낮추는**
근거로 쓰였다. 실제로는 반대였다.

## 5. 그러면 어떤 모델이면 $50을 지키나 — 21개 중 딱 하나, 그리고 그건 nano다

sol-220 발행본의 **토큰 양을 그대로 두고** 이 저장소가 가진 공표 미터
**21개 전부**에 넣어 봤다.

| 모델 · 요율 | 실행당 | |
|---|---:|---|
| `gpt-5.4-pro` standard global long context (가장 비싼 것) | $6,998.66 | 캐시 미터 없음 → 입력 요율로 계산 |
| `gpt-5.6-sol` short standard global | **$411.80** | 실제 하한 |
| `gpt-5.4` standard global | $205.90 | |
| `gpt-5.4` batch global | $103.20 | |
| `gpt-5.4-mini` standard global | $61.77 | 여전히 초과 |
| **`gpt-5.4-nano` standard global** | **$16.84** | **$50 아래로 가는 유일한 요율** |

**21개 중 20개가 $50을 넘는다.** 넘지 않는 하나는 `gpt-5.4-nano`, 판정 모델보다
**두 등급 아래**다.

그러니 "요율만 바꿔서는 불가능하다"고 말하면 틀린다. 정확히는 이렇다 —
**$50을 지키는 길은 있지만, 그 길은 판정을 nano로 내리는 것 하나뿐이다.**
그건 cap 조정이 아니라 **다른 벤치마크**다. nano가 rubric 판정을 얼마나 잘 하는지는
이 저장소에서 **측정된 적이 없다.**

그리고 저 $16.84도 그대로 믿을 값은 아니다. 이 표는 **토큰 양을 고정한 요율 치환**이라
하한 논증일 뿐이다. 실제로 nano로 돌리면 토큰 양 자체가 달라진다 — 지금 출력의
82.3%는 `effort: max`의 reasoning 토큰인데(3.1절), 그건 프런티어 모델의 성질이지
이 워크로드의 성질이 아니다.

남는 결론은 3절과 같다. **cap이나 routing으로는 어느 요율에서도 못 맞춘다.**

## 7. 302 점검표

| # | 명세 | 상태 |
|---|---|---|
| 1 | 토큰/시간 추적 | ✅ 실주행 3회에서 수집 완료. 영수증 장부는 gold-185에만 있고, sol-220 두 건은 per-task 필드로 같은 값에 도달한다(2.1절) |

### 7.1 3번을 여기서 계산하지 않는 이유

운영 한도 값은 이 저장소에서 **제거됐고**, `core/execution_envelope_preflight.py:1711`
이 그 키를 다시 쓰려는 계획을 거부한다. 계정 정보이고 이 계획은 공개되기 때문이다.
그래서 **방법만 적고 값은 적지 않는다.**

```
반복 가능 횟수 = (운영 한도) ÷ (실행당 비용)
```

나눗셈의 아래쪽은 이 문서가 채웠다: **$411.80 ~ $980.84.**
위쪽을 아는 사람이 나누면 된다. 실행 비용을 달러로 적는 것은 규칙에 어긋나지 않는다 —
막혀 있는 것은 *월 크레딧*을 금액과 함께 적는 것뿐이다.

## 8. 그래서 무엇을 할 수 있나 (측정된 크기와 함께)

302의 처방은 못 쓴다. 실제로 크기가 있는 것은 셋이고, **셋 다 소유자 결정이다.**
앞의 둘은 채점기 지문을 움직이므로 **효과를 보려면 유료 재채점이 필요하다.**

| 방향 | 닿는 금액 | 대가 |
|---|---|---|
| **reasoning effort `max` → 낮춤** | 출력의 82.3%, 하한 청구서의 **35.4%** | 채점 품질 영향 **미측정**. 지문이 움직여 재채점 필요 |
| **tool-loop 반복 축소** (`max_iterations: 10`, `per_item_call_cap: 8`) | 미캐시 입력 **51.2%** 를 겨냥 | 같은 대가. smoke 문서의 Option A가 제안한 값들은 지금도 원래대로다 |
| **기준을 지금 파이프라인에 맞게 다시 세움** | — | 비용이 아니라 **기준의 정직성** 문제. 판정을 nano로 내려야만 맞출 수 있는 상수는 예산이 아니다 |

**이 문서는 셋 중 아무것도 하지 않는다.** 302가 요구한 것은 측정과 보고이고,
쓰기 결정은 소유자 게이트다. 지금 확정된 것은 사실 쪽이다 — 얼마가 들었고,
왜 그 처방으로는 안 되고, 무엇이 실제로 크기를 갖는가.

## 9. 이 숫자들이 여전히 "값"이 아닌 이유

317과 같다. 세 축이 열려 있다.

| 축 | 상태 |
|---|---|
| tier (short / long context) | 미확정 — 그래서 범위다. 커밋된 장부 전체(sol 호출 45,203회)에서 최대 단일 요청 **226,701 토큰**, `gpt-5.4`의 공개 경계 272,000 초과 **0건** |
| zone (global / data zone) | 미확정 — 약 1.1배 |
| cache-write | **적용 불가** — 미터는 있는데 write 토큰 수가 기록되지 않는다. gold-185 최악의 경우 미캐시 56,284,648 토큰에 **+$351.78** |

`estimated_cost_usd`는 세 실행 모두 `null`이다. **`0`이 아니다.**
`0`은 "공짜였다"이고 `null`은 "아무도 얼마인지 말할 수 없다"이다.

## 10. 부수 발견 — 발행된 인덱스가 `$0`을 싣고 있다
