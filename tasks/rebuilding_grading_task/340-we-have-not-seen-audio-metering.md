# 340 — 소리 계측을 우리는 아직 못 봤다

**한 문장으로:** `337`이 소리를 열 번 보내고 사용량을 열 번 받아 왔지만, 그
사용량은 **원장에 한 번도 안 들어갔다.** `337`의 진단 스크립트는 계측기를 아예
안 끼운다. 그래서 §11.9의 *"소리 계측은 검증되지 않았다"*는 **`337` 이후에도
그대로 참**이고, 이 문서는 그 구멍을 모의로 메운 뒤 **실제로 재려면 무엇을
못 박아야 하는지**를 적는다.

**이번에 모델은 한 번도 안 불렀다.**

---

## 0. 왜 이 문서가 필요했나

`TASK_PER_TASK_COST_RECEIPTS.md` §11.9가 열린 항목으로 남긴 문장:

> 소리 계측은 이 Smoke로 **검증되지 않았다** — 실행되지 않았기 때문이다.

그 뒤에 `337`이 소리를 열 번 보냈다. 그러면 이제 검증된 것인가?

**아니다.** 그리고 그 이유가 이 문서의 §2다.

---

## 1. 세 갈래를 갈라 놓는다

섞으면 안 되는 세 가지가 있다. 이 문서는 끝까지 갈라 놓는다.

| | 무엇으로 아나 | 이 문서에서 |
|---|---|---|
| **㉮ 원본이 증명하는 것** | `337`이 이미 남긴 파일 | §2 |
| **㉯ 모의가 증명하는 것** | 진짜 운영 코드 + 가짜 응답 | §3 §4 |
| **㉰ 아무도 아직 안 본 것** | 실제 유료 호출이 필요하다 | §5 §6 |

㉮와 ㉯를 합쳐서 *"검증됐다"*고 쓰면 안 된다. 둘은 **다른 층**을 본다.

## 2. ㉮ `337`의 원본이 실제로 증명하는 것

### 2.1 증명하는 것

`337-audio-accuracy-measured.json`에서 직접 읽은 값이다.

| | |
|---|---|
| 호출 | 10건 |
| `usage_complete` | **10건 전부 `true`** |
| 입력 토큰 합 | 4,095 |
| 출력 토큰 합 | 553 |
| 오디오 토큰 | 호출당 30~34, 합 **320** |
| `audio_tokens_billed` | 호출마다 `audio_tokens`와 **같다** |
| `api_call_count` 합 | 10 |
| 소리를 실은 요청 | 10 / 10 |

**여기까지가 진짜 잰 것이다.** 어댑터(`core/perception/audio.py`)가 응답에서
사용량을 읽어 자기 반환값에 담는 것 — 이 한 층은 실제 유료 호출로
확인됐다.

### 2.2 그런데 비용 칸은 **계측이 아니다**

`337`의 비용 칸은 이렇게 생겼다.

```json
"cost": {
  "pricing_complete": false,
  "unpriced_models": ["gpt-audio-1.5"],
  "estimated_cost_usd": null,
  "note": "... null, not $0."
}
```

읽으면 *"가격표를 조회했고 없었다"*처럼 보인다. **아니다.** 그 칸을 만드는
코드(`scripts/measure_audio_grading_accuracy.py:3610`)는 이렇다.

```python
"pricing_complete": not billable,
"unpriced_models": [identity["audio_deployment"]] if billable else [],
"estimated_cost_usd": None,
```

`billable`은 그냥 *"유료 실행이었나"*다(`3545`행: `billable = model_calls if
measured else 0`). 즉:

* `pricing_complete: false`는 **가격표를 본 결과가 아니다.** 유료로 돌면 무조건
  `false`가 찍힌다.
* `unpriced_models`도 **조회 결과가 아니다.** 배포 이름을 그대로 옮긴 것이다.
* `estimated_cost_usd: None`은 **상수다.** `if`도 없다.
* `note`의 *"gpt-audio-1.5 is absent from the price table"*도 **사람이 써 넣은
  문장**이다. 실행 중에 확인한 게 아니다.

가장 확실한 증거는 반대쪽이다. **모의 실행(`--dry-run`)은 `billable`이 0이라
`pricing_complete: true`를 찍는다** — 가격이 없는 모델인데 *"가격 정보 완비"*라고
말한다. 조회를 했다면 나올 수 없는 값이다.

**우연히 맞는 값이다.** `gpt-audio-1.5`는 정말로 가격표에 없다
(`experiments/execution_envelope/model_price_table.json`의
`models_deliberately_not_priced`, 2026-09-07 재확인). 하지만 **가격이 있었어도
저 넷은 똑같이 찍혔다.**

### 2.3 그리고 원장을 한 번도 안 건드린다

확인한 방법 — 그 스크립트 4,131행 전체에서 찾아봤다.

```
$ grep -n 'MeteredClient|\.meter\(|CostRecorder|CostReceiptLedger|
          open_cost_recorder|price_call|load_receipt_price_table' \
        scripts/measure_audio_grading_accuracy.py
(없음)
```

클라이언트를 어떻게 만드는지도 봤다(`4028`행).

```python
perception = AudioPerception(
    client=wire,        # 계측기를 안 씌운 생 클라이언트
```

운영 채점기는 이렇게 안 한다(`core/grader.py`).

```python
self._perception_client = cost_recorder.meter(
    client, provider="azure", stage=STAGE_PERCEPTION)
AudioPerception(client=self._perception_client, ...)
```

**그래서 `337`이 산 열 번의 호출은 계측 경로를 한 뼘도 안 지나갔다.** 원장 행
0개, 가격 적용 0회, 영수증 0장, `grading_cost` 반영 0건.

> 사용자가 미리 지적한 그대로다 — *"`337`의 10회에 usage가 있는 것과, 운영 채점
> 호출이 공통 원장 → 과제별 `grading_cost` → 보고서에 반영된다는 것은
> 별개입니다."* **별개였다.**

## 3. ㉯ 운영 경로를 모의로 몰아 봤다

그래서 진짜 운영 경로 —
**`Grader` → `cost_recorder.meter()` → `AudioPerception` → `MeteredClient` →
`CostReceiptLedger` → 영수증** — 에 **가짜 응답만** 넣고 몰아 봤다. 설정도
운영이 쓰는 `grading_configs/default_v2.yaml`을 그대로 읽는다.

새 파일: `batch-runner/tests/test_a_broken_audio_reply_still_costs_what_it_cost.py`
(14건, 전부 통과).

### 3.1 형식이 깨져도 사용량은 안 사라진다 — 이게 핵심이었다

| 무엇이 일어났나 | 판정 | 원장에 남은 것 |
|---|---|---|
| JSON이 아닌 산문이 왔다 | `format_error:unparseable_json` | `settled`, **1000/200/30/10 그대로** |
| JSON은 읽혔고 모델이 판정을 거절했다 | `sub_judge_declined` | `settled`, **1000/200/30/10 그대로** |

**왜 안 사라지냐:** `_around`가 `settle`을 **응답 직후, 파싱 전에** 부른다.
봉투를 열어 보기 전에 이미 정산이 끝나 있다.

이게 우연이 아니란 걸 확인하려고, `settle`을 파싱 **뒤로** 옮긴 변종을
만들어 돌렸다. 그 테스트가 실패한다. 즉 **`334`·`335`·`337`처럼 답장이 전부
깨지는 실행은, 그 변종에서라면 오디오 지출 전체가 "불명"으로 찍힌다.**

### 3.2 나머지 열둘

| 상황 | 실제로 나온 결과 |
|---|---|
| 정상 응답 | `settled`, 금액 계산됨 |
| **사용량 칸이 아예 없는 응답** | `settled`, 토큰 전부 `None`, `usage_absent`, **호출 수는 1로 센다** |
| **API 전 실패** (파일 없음) | 전선 호출 0, **원장 행 0**, 영수증 `not_run` |
| 거절 뒤 이름으로 거절된 문항들 | 요청 1건만 나감, **행도 1개만**, 나머지는 `audio_unavailable:provider_400` |
| `500` | 행이 `reserved`로 남음 → `call_reachability_unknown`, 영수증 `partial` |
| `400` | **`500`과 완전히 같다** — §5.2에서 다시 다룬다 |
| 실패 1건 + 성공 2건 | `partial`인데 **아는 금액 2건은 그대로 보고한다** ($0.118) |
| 오디오 몫 = 지분인가 | **$0.059**. 위에 얹어 세면 $0.061이었을 것 |
| 오디오 토큰 > 입력 토큰 | `usage_partial` (`price_missing` 아님) |
| 모델은 가격 있고 소리 요율은 없음 | `price_missing` |
| ↑ 같은 표, 소리 0인 호출 | **가격이 매겨진다** — 거절이 표 때문이 아니라 소리 때문임을 증명 |
| 재개 (`continue_rounds=True`) | 0→1회차, 1→2행, $0.059→$0.118, 식별자 서로 다름 |
| 같은 정산 두 번 (같은 값) | 조용한 무동작, 1행 유지 |
| 같은 정산 두 번 (다른 값) | `LedgerIntegrityError` — **기록된 비용을 덮지 않는다** |
| 지각 비용이 `problem_solving_cost`에 섞이나 | **안 섞인다.** 항상 `grading_cost`, 문제풀이 쪽은 `not_run` |

### 3.3 이 14개가 실제로 무언가를 잡는지 확인했다

처음 돌렸을 때 14개가 다 통과했다. 그건 **테스트를 가장 못 믿을 때**다. 그래서
운영 코드를 여덟 가지로 망가뜨려(monkeypatch, 파일은 안 고침) 각각 잡히는지
봤다.

| 무엇을 망가뜨렸나 | 몇 개 실패 | 잡은 테스트 |
|---|---|---|
| `settle`을 무동작으로 | 9 | (여러 개) |
| `settle`을 파싱 뒤로 | 1 | 형식 실패 |
| 사용량 없으면 행을 버리게 | 1 | 사용량 없는 응답 |
| 오디오를 위에 얹어 계산 | 8 | (여러 개) |
| 소리를 글자 요율로 계산 | 1 | 소리 요율 없는 표 |
| 불명 1건이 작업 전체를 0으로 | 1 | 불명 옆의 아는 금액 |
| 재개가 회차를 잊게 | 1 | 재개 |
| 모순되는 정산을 덮게 | 1 | 중복 정산 |

**여덟 가지 다 잡혔고, 각각을 지킨다고 주장한 테스트가 잡았다.**

## 4. ㉯ 가격이 없는 것과 사용량이 없는 것은 **다르다**

두 결핍을 따로 검증했다. 섞이면 안 되는 이유는, 읽는 사람이 **다른 곳을
고치러 가야** 하기 때문이다.

| 결핍 | 이유표 | 고칠 곳 |
|---|---|---|
| 모델이 가격표에 없다 | `price_missing` | 가격표 |
| 모델은 있는데 **소리 요율**이 없다 | `price_missing` | 가격표 (같은 이유표, **다른 원인**) |
| 제공자가 사용량을 안 줬다 | `usage_absent` | 제공자 / 요청 |
| 사용량이 모순된다 (소리 > 전체) | `usage_partial` | 제공자 응답 |
| 소리 요율은 있는데 분해값이 `None` | `usage_partial` | 제공자 응답 |

`price_missing`이 두 원인을 공유하는 건 **의도된 것**이다
(`cost_receipts.py:600` 주석: *"…exactly as it is when the model is absent from
the table altogether"*). 그래서 그 둘을 갈라 놓는 음성 대조군을 넣었다 — 같은
표로 **소리 0인 호출은 가격이 매겨진다.** 표가 문제가 아니라 소리가 문제라는
뜻이다.

**모든 결핍에서 금액은 `null`/미확정이고 `$0`이 아니다.** 비슷한 모델 요율로
메우지 않았고, `gpt-audio-1.5`에 값을 넣지도 않았다.

가격표 자신이 그렇게 되어야 한다고 적어 놨다 —
`models_deliberately_not_priced["azure:gpt-audio-1.5"]`의 `consequence`:

> Audio perception calls stay unpriced, and any receipt containing one stays
> partial.

§3이 확인한 게 **운영 코드가 실제로 그렇게 한다**는 것이다. 적어 둔 것과 도는
것이 같은지는 따로 봐야 하는 문제고, 이번엔 같았다.

## 5. 아직 안 본 것

### 5.1 모의로는 절대 못 보는 것

| | 왜 |
|---|---|
| 실제 Azure 응답의 사용량 칸 모양 | 가짜 응답은 내가 만든 모양이다. 실제 배포가 `prompt_tokens_details.audio_tokens`를 그 자리에 넣는지는 **응답을 받아 봐야** 안다 |
| 오디오 토큰이 정말 입력 **안에** 있는지 | $0.059냐 $0.061이냐가 여기 걸린다. 지금은 **가격표 계약**이 그렇게 정한 것이고, `gpt-audio-1.5` 청구서로 대조한 게 아니다 |
| SDK 내부 재시도 | `339` §9와 같은 한계. SDK가 안에서 3번 치면 이 층은 1번으로 본다 |
| 실제 `step8_grade` 실행에서 원장이 생기는지 | 모의는 원장을 직접 만들었다. 운영은 `open_cost_recorder`가 만든다 |

### 5.2 이미 아는 결함 하나

`400`이 `500`과 똑같이 `call_reachability_unknown`으로 찍힌다. **금액은 맞고
이유가 틀렸다** — `400`은 답장이 온 것이므로 도달 여부가 불명확하지 않다.

**여기서 안 고쳤다.** 고칠 자리가 공용 `core/cost_metering.py`다. 실패하는
테스트와 제안 diff, 그리고 그 제안이 기존 1,671개 중 **정확히 1개**만
건드린다는 측정까지 [`341`](./341-what-a-refused-call-costs.md)에 있다.

### 5.3 이미 검증돼 있어서 **안 다시 만든 것**

이건 구멍이 아니다. 확인하고 넘어간 것이다.

| 구간 | 이미 지키는 테스트 |
|---|---|
| 영수증 → 과제별 `grading_cost` → 보고서 | `test_a_missing_receipt_is_a_hole_not_a_zero.py` (영수증 없는 행은 `$0`이 아니라 **구멍**) |
| 파이프라인 경계 | `test_cost_receipts_reach_the_pipeline_boundaries.py` |
| 재개·샤드 병합 | `test_cost_receipts_survive_resume_and_shard_merge.py` |
| 성공한 지각 읽기 | `test_a_perception_read_reaches_the_receipt.py` |
| 실패가 문항 칸을 안 먹는 것 | `test_a_failed_audio_call_does_not_cost_the_task_its_turn.py` |

**§3의 새 파일은 이 중 어느 것도 다시 안 짠다.** 새 파일이 보는 건 *"실패했을
때"*이고, 위 다섯은 *"성공했을 때"*와 *"영수증이 없을 때"*를 본다.

## 6. 최소 실전 계측 시험 — 실행 전에 못 박을 것

**아직 발주 안 한다.** 이 절은 발주할 수 있는 상태로 만들어 두는 것이다.

### 6.1 이건 정확도 시험이 **아니다**

가장 중요한 구분이다.

| | 정확도 연구 (`331`·`337`·`338`) | **계측 시험 (이 절)** |
|---|---|---|
| 묻는 것 | 채점기가 소리를 맞게 판정하나 | **쓴 돈이 영수증에 남나** |
| 판정이 다 틀리면 | 실패다 | **상관없다** |
| 판정이 다 안 읽히면 | 실패다 | **상관없다 — 오히려 좋은 시험이다** |
| 필요한 표본 | 통계적으로 유의할 만큼 | **1과제 · 소수 호출** |
| 결론에 쓸 수 있나 | 사전등록한 것만 | 계측 이야기만 |

`337`이 남긴 상황이 이 시험에 **유리하다.** 답장이 대부분 깨졌으므로,
*"깨진 답장도 계측되나"*를 실전에서 볼 수 있는 조건이 이미 갖춰져 있다.

### 6.2 무엇을 확인하나 — 통과 조건

전부 **원장과 영수증**에 대한 조건이다. 판정 내용에 대한 조건은 하나도 없다.

| # | 조건 |
|---|---|
| 1 | 원장에 `stage=perception` 행이 **보낸 요청 수와 같은 개수** 생긴다 |
| 2 | 소리를 실은 행마다 `audio_input_tokens > 0` |
| 3 | 어댑터가 보고한 입력/출력 토큰이 원장 행의 값과 **일치**한다 |
| 4 | `gpt-audio-1.5`가 가격표에 없으므로 이유표는 `price_missing`, 금액은 **`null`** |
| 5 | 그 작업 영수증의 `grading_cost`가 그 지각 호출들을 담는다 |
| 6 | 같은 작업의 `problem_solving_cost`가 **안 움직인다** |
| 7 | 판정이 깨진 문항의 호출도 **1·2·3을 만족한다** |
| 8 | 보고서에 `grading_cost`가 찍히고, 그 값이 `$0`이 아니라 미확정으로 나온다 |
| 9 | 원장을 다시 읽어 만든 합이 실행 중 영수증과 같다 |

**하나라도 어긋나면 그게 결과다.** 통과가 목표가 아니다.

### 6.3 한계 — 실행 전에 정하고, 실행 중에 안 바꾼다

| | 값 | 왜 이 값인가 |
|---|---|---|
| 과제 | **1개** | 계측은 과제 수로 좋아지지 않는다 |
| 소리 문항 | **2개** | 1개면 "행이 1개 생겼다"가 우연과 구분이 안 된다. 2개면 개수가 맞는지 볼 수 있다 |
| 클립 | `330` 매니페스트의 **`crate`, `shelf`** | 이미 지문이 박혀 있다 (§6.4) |
| 최대 모델 요청 | **6** (문항 2 × 여유 3) |
| 전송 재시도 | **0** | 재시도 계측은 이 시험의 질문이 아니다. 실패하면 실패로 기록하고 끝낸다 |
| 유료 구간 벽시계 상한 | **10분** | `337`의 유료 job이 2분 50초였다 |
| 유료 job 실패 시 | **재발주 안 함.** 나온 것만 기록한다 |
| 예산 | 6회 × `gpt-audio-1.5`. **금액은 미확정** — 가격이 없으므로 상한을 달러로 못 쓴다. **요청 수가 상한이다** |

> 마지막 줄이 중요하다. 이 모델은 요율이 없으니 *"$X까지"*라고 쓸 수 없다.
> 그래서 상한을 **호출 수**로 잡았다. 새 비용 상한 장치를 만드는 게 아니라,
> 이미 있는 `call_cap`(`pins.audio_call_cap_per_task = 32`)보다 훨씬 낮은
> 값을 이 실행에만 지정하는 것이다.

### 6.4 실행 전에 박아 둘 지문

발주 전에 아래를 문서에 적고, 실행 중 측정기가 **다시 계산해서 대조**한다
(`337` §2가 한 방식 그대로).

| 무엇 | 어디서 오나 | 지금 값 |
|---|---|---|
| 클립 `crate` | `330-speech-verification-manifest.json` → `clips[].sent.sha256` | `7e59f9a516ff6bf3…` |
| 클립 `shelf` | 같음 | `2737aed8fa5d09a7…` |
| 오디오 배포 | 채점 설정 | `gpt-audio-1.5` |
| 전송 형식 | `330`이 못 박음 | `wav` · 16,000 Hz · 모노 |
| eSpeak | 매니페스트 `provenance` | `1.51+dfsg-12build1`, 이진 `34191438b1e0f8f5…` |
| 채점기 원본 지문 | 실행 시점에 계산 | **발주 시 박는다** |
| 가격표 지문 | `model_price_table.json` | **발주 시 박는다** |
| 채점 설정 지문 | `grading_configs/default_v2.yaml` | **발주 시 박는다** |

> `crate`의 `7e59f9a5…`가 `337`이 **실제로 보낸** digest와 같다는 걸
> 확인했다(`337-audio-accuracy-measured.json` → `delivery.digests_per_clip`).
> 즉 이 지문은 종이 위의 값이 아니라 **한 번 실전에서 대조된 값**이다.

### 6.5 이 시험이 **못 말할 것** — 미리 적어 둔다

| | |
|---|---|
| 금액이 맞는지 | 요율이 없다. 사용량이 **보존되는지**까지다 |
| 오디오 토큰이 입력 안에 있는지 | 청구서를 봐야 안다. 이 시험은 계약대로 계산되는지만 본다 |
| 실패율 | 2문항이다. 비율이 아니다 |
| 판정 정확도 | **묻지 않는다** (§6.1) |
| 다른 모델 | `gpt-audio-1.5` 하나다 |
| SDK 내부 재시도 | 여전히 안 보인다 |

### 6.6 발주 전에 남은 것

1. 이 문서에 **채점기·가격표·설정 지문 3개**를 박는다 (§6.4의 빈 칸).
2. 1과제 2문항짜리 채점 설정을 **따로** 만든다 — 기존 설정이 `task_ids`를
   고정해 두면 `--tasks`로 좁힐 수 없다.
3. §6.2의 9개 조건을 검사하는 **후처리 검증기**를 먼저 짠다. 실행 뒤에 짜면
   결과를 보고 조건을 고르게 된다.
4. 그리고 **소유자 승인**. 이번 전달 범위는 로컬 코드·테스트·문서와 읽기
   전용 확인까지다.
