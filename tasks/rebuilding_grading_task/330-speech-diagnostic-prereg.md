# 330 — 말소리 진단 사전등록 (아직 안 샀다)

**상태: 사전등록 초안. 아직 한 푼도 안 썼다.**

이 문서는 **돈을 쓰기 전에** 적는다. 실행 후에 조건을 바꾸면 그건 사전등록이 아니다.
[`328`](./328-the-answer-that-was-not-in-the-vocabulary.md)이 실패한 이유의 절반이
"무엇을 재는지 실행 전에 못 박지 않은 것"이었다.

---

## 0. 실행 조건 (이게 안 맞으면 안 산다)

| 조건 | 상태 |
|---|---|
| 응답 형식 계약 PR이 **green으로 병합** | ⬜ PR #435 |
| 말소리 세트가 **CI에서 실제로 만들어짐** | ⬜ artifact + manifest |
| 매니페스트 digest를 이 문서에 **기입 완료** | ⬜ §2 |

세 개 다 채워지기 전에는 실행하지 않는다. **⬜ 가 하나라도 남아 있으면 이 문서는
사전등록이 아니라 계획서다.**

---

## 1. 무엇을 묻는가

> **`gpt-audio-1.5`가 말소리를 알아듣는가?**

지금까지 잰 건 전부 톤·클릭·비프였다. 그걸로 "판정이 소리에 따라 달라지는가"는
답했다. 하지만 채점 대상 31건 중 **사인파는 하나도 없다.** 전부 사람 말이다.

이건 [`324`](./324-the-speech-it-heard-in-silence.md)나
[`328`](./328-the-answer-that-was-not-in-the-vocabulary.md)이 물은 것과 **다른 질문**이고,
한쪽만 가질 수 있는 능력이다.

### 이번에 안 묻는 것

* **프롬프트 A/B 아님.** 갈래는 **하나**다(운영 헤더). 두 질문을 한 실행에 섞으면
  둘 다 흐려진다. [`328`](./328-the-answer-that-was-not-in-the-vocabulary.md)이 그랬다.
* **기존 실험 재채점 아님.** 185실행·31건은 건드리지 않는다.
* **음악·신호 재측정 아님.** 톤 코퍼스 결과와 **따로** 보고한다. 섞지 않는다.

---

## 2. 고정하는 것

### 모델·설정

| | 값 |
|---|---|
| 모델 | `gpt-audio-1.5` (Azure OpenAI) |
| 설정 파일 | `gold_audio_repeat_v2_sol_max.yaml` |
| 채점기 지문 | `8bb8360a5da68fc532b3d7392f726b284e1940417170563079a1550d0458c8a8` |
| 구조화 출력 | **끔** — API가 `input_audio`와 함께 받는지 미확인 |

### 프롬프트

운영 헤더 + `AUDIO_RESPONSE_CONTRACT`. **손으로 고쳐 쓰지 않는다.**
[`329`](./329-the-verdict-that-was-never-a-verdict.md)에서 두 갈래를 바이트 단위로
맞춘 그 문장 그대로다.

모델이 보는 건 `criterion` **한 줄**이다. 대본도, 정답도, 짝의 반대쪽도 안 간다.

### 음성

`speech-verification-set.yml` 산출물. **아래는 CI 실행 뒤에 채운다.**

| | 값 |
|---|---|
| espeak-ng 버전 문자열 | ⬜ *(manifest `provenance.version_string`)* |
| 바이너리 SHA-256 | ⬜ |
| 패키지·출처 | ⬜ |
| 재인코더 (PyAV/ffmpeg) 버전 | ⬜ *(manifest `encoder`)* |
| 생성 명령 | ⬜ *(manifest `clips[].command`)* |
| 클립 10개 **합성 원본** SHA-256 | ⬜ *(`clips[].source.sha256`, 22050 Hz)* |
| 클립 10개 **실제 전달본** SHA-256 | ⬜ *(`clips[].sent.sha256`, 16000 Hz — **모델이 듣는 것**)* |
| 총 재생 길이 | ⬜ 초 |
| 워크플로 실행 ID | ⬜ |

지문이 두 개인 이유는 [`329`](./329-the-verdict-that-was-never-a-verdict.md) §6에
적었다. 한 줄로 줄이면: eSpeak는 22050 Hz로만 쓰고, 채점 경로가 16000 Hz로 다시
인코딩해서 보낸다. **들려준 게 뭐였냐**를 증명하는 건 `sent` 쪽이다.

**빈칸을 채우지 않은 채로 실행하면 안 된다.** 어떤 소리를 들려줬는지 나중에
증명할 수 없는 측정은 측정이 아니다.

### 문항·반복·호출

| | 값 |
|---|---|
| 클립 | 10 |
| 주장 | **20** (짝 10쌍, 참 10 / 거짓 10) |
| 갈래 | 1 (운영) |
| 반복 | **3** — 이전 실행들과 같게. 안정성을 비교하려면 같아야 한다 |
| **총 호출** | **20 × 3 × 1 = 60** |
| 찍으면 | **50%** |

### 토큰 예상

[`328`](./328-the-answer-that-was-not-in-the-vocabulary.md)에서 공급자가 보고한 값은
**클립 1초당 정확히 10.00 오디오 토큰**이었다. 그 비율을 그대로 적용하면:

```
예상 오디오 토큰 = 10 × (총 재생 길이 초) × 3
```

실제 값이 이 식에서 **10% 넘게 벗어나면 그 자체가 보고 대상**이다. 소리가 다르게
전달됐거나 과금 방식이 바뀐 것이므로.

### 비용

`gpt-audio-1.5`는 **가격표에 없다.** 따라서:

* `pricing_complete: false`
* `estimated_cost_usd: null`

**`$0`이 아니다.** 모르는 것은 모른다고 적는다. 실제 청구액은 나중에 대조한다.

## 3. 시간·중단 규칙

실행 전에 정한다. 중간에 "조금만 더"는 없다.

| 상황 | 조치 |
|---|---|
| 벽시계 **20분** 초과 | 중단, 그때까지 나온 것만 보고 |
| 처음 **10번** 중 **응답률 0** | **즉시 중단.** 형식이 또 깨진 것이므로 나머지 50번은 낭비 |
| `provider_failure` 누적 **10번** | 중단. 인프라 문제지 모델 능력 문제가 아니다 |
| 소리 미전달(오디오 토큰 0) 감지 | **즉시 중단.** 안 들려준 걸로 능력을 재면 안 된다 |
| 그 외 | 60번 다 채운다 |

중단해도 **결과는 그대로 보고한다.** 중단은 실패가 아니라 절약이다.

## 4. 미리 정하는 지표

### 1차 지표

> **쓸 수 있는 판정 중 정확도**, 그리고 그 옆에 **시도 전체 대비 응답률**.

두 숫자를 항상 같이 낸다. 하나만 내면 "0번 답했다"가 안 보인다.

### 판정 규칙

| 결과 | 읽는 법 |
|---|---|
| 정확도가 50%를 **유의하게 넘음** | 말소리를 어느 정도 알아듣는다는 **증거** |
| 정확도가 50% 근처 | 이 세트로는 **말소리 이해를 못 보였다** |
| 응답률이 낮음 | 능력이 아니라 **형식** 문제. 능력 판정 안 함 |

유의성은 20개 주장 각각에 대해 3회 중 다수결로 하나의 판정을 정한 뒤,
**이항검정(n = 20, p = 0.5)**으로 본다. 반복 3회를 독립 시행으로 세면 분모가
부풀어서 없는 유의성이 생긴다.

### 부차 지표

* 짝 안에서의 **일관성** — 같은 클립, 참/거짓 한 쌍에 대해 서로 다른 답을 하는가.
  둘 다 `pass`면 안 듣고 찍은 것이다.
* 종류별 정확도 — `order` / `binding` / `negation`은 단어만 주워담아선 못 푼다.
  다른 종류는 되는데 이 셋만 안 되면 **"단어는 듣지만 문장은 못 듣는다"**는 뜻이다.
* 반복 3회 사이의 **불일치율** — 이전 실행의 19.35%와 비교 가능하다.

## 5. 결과가 말할 수 있는 것과 없는 것

**미리** 적는다. 숫자를 본 뒤에 정하면 갖다 붙이는 게 된다.

| | |
|---|---|
| ✅ 통과하면 | 합성 음성을 알아듣는다. 사람 목소리도 알아들을 **가능성이 높다** |
| ❌ 실패하면 | **eSpeak를** 못 알아듣는다. "사람 말을 못 알아듣는다"는 **말할 수 없다** |
| ❌ 어떤 경우든 | 오디오 토큰이 청구됐다는 건 **전달의 증거**이지 이해의 증명이 아니다 |
| ❌ 어떤 경우든 | 이 결과는 **말소리**에 대한 것이다. 톤·클릭·비프 결과와 섞지 않는다 |
| ❌ 어떤 경우든 | 20문항은 **적다.** 좁은 신뢰구간을 주장하지 않는다 |

eSpeak NG는 로봇 목소리라 사람 목소리보다 **알아듣기 어렵다.** 그래서 통과는 강한
증거이고 실패는 약한 증거다. 이 비대칭은 매니페스트의 필드로도 들어간다.

---

## 6. 무엇을 발표하고 무엇을 안 하나

* 발표: 정확도, 응답률, 미응답 3분류, 종류별 정확도, 짝 일관성, 토큰, 지문
* 발표 안 함: 오디오 파일 자체(라이선스), 모델의 추론 내용, 프롬프트 전문
* **`data/grades`에 안 쓴다.** 이건 진단이지 채점이 아니다. 대시보드에도 안 올린다
* **185실행·31건 수치는 하나도 안 고친다**
