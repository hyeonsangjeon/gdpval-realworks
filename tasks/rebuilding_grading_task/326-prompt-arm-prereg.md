# 326 — 프롬프트를 바꿔서 다시 묻는다 (사전등록)

**실행 전에 쓴다.** 아래 조건과 분석 방법은 결과를 보기 전에 고정했다. 결과가
나온 뒤에 기준을 옮기지 않기 위해서다.

[`324`](./324-the-speech-it-heard-in-silence.md)는 오디오 판정자가 소리를 따라
움직이지 않는다는 것까지 보여줬고, [`325`](./325-what-the-wire-carried.md)는
"소리가 안 갔다"는 설명을 지웠다. 남은 두 설명은 이것이다.

> **프롬프트** — 갔지만 질문이 답을 끌고 갔다.
> **능력** — 갔고 질문도 공정한데 못 들었다.

이 실험은 **같은 소리·같은 문항에 프롬프트만 바꿔** 그 둘을 가른다.

---

## 1. 고정하는 것

| | 값 |
|---|---|
| 모델 · 배포 | `gpt-audio-1.5` / `gpt-audio-1.5` |
| 공급자 · 경로 | Azure OpenAI, Chat Completions |
| 설정 | `gold_audio_repeat_v2_sol_max.yaml` |
| 클립 | 9개, 코드로 생성, 324와 같은 생성기 |
| 기준 문항 | 20개(참 10 · 거짓 10), 324와 **한 글자도 안 바꿈** |
| 반복 | 갈래마다 3번 |
| 호출 | 20 × 3 × 2 = **120번** |
| 응답 상한 | 두 갈래 동일 |
| 잘림 | `trim_seconds: 30`, 두 갈래 동일 |

**바꾸는 것은 프롬프트의 머리말 하나뿐이다.** 오디오 조각은 갈래를 바꿔도
**같은 객체를 그대로 넘긴다.** 다시 인코딩하지 않는다. 두 갈래가 정말 같은
바이트를 들었는지는 보고서의 `delivery.clips_with_more_than_one_digest`가
확인한다 — 여기에 클립 이름이 하나라도 뜨면 이 실험은 무효다.

## 2. 두 갈래

**대조(`production`)** — 지금 채점기가 쓰는 프롬프트를 **그대로** 보낸다.
다시 구현한 게 아니라 요청을 손대지 않고 통과시킨다. 그래서 대조군이 진짜
운영 프롬프트라는 것이 구조로 보장된다.

**처치(`observation`)** — 머리말만 바꾼다. 바꾸는 내용은 다섯 가지다.

1. 오디오가 입력으로 들어왔고 **거기서만** 판단하라고 말한다.
2. **먼저 관찰하고 나서 판정하라**고 순서를 지정한다 (길이·유무·사건 수와 시각·
   음높이와 화성).
3. 문장이 **참일 수도 거짓일 수도** 있다고 명시한다.
4. **문장에 적힌 숫자는 검증 대상이지 사실이 아니라고** 못 박는다.
5. 못 정하겠으면 찍지 말고 `judge_error`를 내라고 한다.

**정답은 주지 않는다.** 문항별로 답을 암시하지 않고, 참·거짓 비율도 알려주지
않으며, 기준 정답도 모델에 넘기지 않는다. 시험 하나가 머리말 안에 클립 이름·
정답·"10 true"류의 문자열이 없는지 확인한다. 응답 봉투(JSON 형식)는 두 갈래가
같아서, 형식 차이로 응답률이 갈리지 않게 했다.

> **이 실험이 재는 건 다섯 가지의 묶음이다.** 어느 하나가 효과를 냈는지는
> 이 설계로 갈리지 않는다. 묶음이 아무것도 못 바꾸면 다섯 개를 하나씩 뜯을
> 이유도 약해지고, 묶음이 바꾸면 그때 뜯는 게 순서다.

## 3. 왜 예전 60번을 재활용하지 않나

324의 60번을 대조군으로 쓰면 60번을 아낄 수 있다. 안 쓴다. 그 60번은 다른 날
다른 배포 상태에서 산 것이고, 그사이에 모델이 바뀌었는지 우리는 모른다.
**시점 차이가 프롬프트 효과로 보일 수 있다.**

그래서 대조군을 새로 산다. 게다가 두 갈래를 **번갈아** 부른다 — 문항마다
대조 → 처치 순으로 붙여서, 시간에 따라 흐르는 것이 있으면 두 갈래에 똑같이
묻게 한다. 갈래를 몰아서 돌리면(60번 대조 후 60번 처치) 그게 안 된다.

## 4. 미리 정한 분석

**짝짓기.** 같은 `(문항, 회차)`가 한 짝이다. 60짝이 나온다. 한쪽이라도
빠지면 그 짝은 버린다.

**1차 지표 — 맞힘의 짝 비교.** 처치만 맞은 짝을 `b`, 대조만 맞은 짝을 `c`로
세고, **정확 이항 McNemar(양측)** 를 쓴다.

```
p = min(1, 2 · Σ_{i ≤ min(b,c)} C(n, i) / 2ⁿ),  n = b + c
```

엇갈린 짝이 하나도 없으면 p는 **`1.0`이 아니라 `null`** 이다. 잴 것이 없었다는
뜻과 차이가 없다는 뜻은 다르다.

**2차 지표.**
* 갈래별 판별력 J = P(pass | 참) − P(pass | 거짓)
* 갈래별 **응답률** = 답한 호출 ÷ 전체 시도
* 갈래별 정확도(답한 것 기준)

**정확도와 응답률을 반드시 같이 낸다.** 처치 갈래는 "모르겠으면 `judge_error`"를
허용하므로, 어려운 문항을 골라 버리고 정확도만 올릴 수 있다. 응답률 없이 정확도만
보면 그게 개선처럼 보인다. 보고서의 모든 집계 칸에 분모가 함께 나오게 했고,
시험이 그걸 강제한다.

**이 설계가 잡을 수 있는 크기.** 엇갈린 짝이 6개 미만이면 어떻게 갈려도
p < 0.05가 **불가능**하다. 6짝이 전부 한 방향이면 p = 0.0312. 12짝이면 10:2까지,
20짝이면 15:5까지 가야 0.05를 넘는다. **즉 이 실험은 작은 개선을 못 본다.**
못 본 것과 없는 것은 다르다.

**미리 정한 읽기.**

| 결과 | 쓸 문장 |
|---|---|
| 처치가 유의하게 낫다 | 프롬프트가 원인의 **일부**다. 능력 문제로 단정할 수 없다 |
| 차이가 유의하지 않다 | **이 코퍼스·이 크기에서 차이를 못 찾았다.** 두 프롬프트가 같다는 뜻이 아니다 |
| 엇갈린 짝이 0 | 잴 것이 없었다. p는 `null` |
| 처치가 유의하게 나쁘다 | 관찰 지시가 해가 됐다. 그것도 결과다 |

보고서가 내는 `reading` 문장에 **"does NOT mean the prompts are equivalent"** 가
들어가고, 그 문장이 사라지면 시험이 깨진다.

## 5. 비용과 원장

| | 값 |
|---|---|
| 호출 | **120** (대조 60 · 처치 60) |
| 모델 | `gpt-audio-1.5` |
| 가격표 | **없음** |
| 금액 | **`null`** — `$0`이 아니다 |

`gpt-audio-1.5`는 저장소 가격표에 없다. 보고서는 `pricing_complete: false`,
`estimated_cost_usd: null`을 낸다. **돈은 나가고 액수는 모른다.** 호출마다의
사용량(입력·출력 토큰, 오디오 토큰 보고 여부)은 전부 기록한다.

점수는 하나도 안 쓴다. 과제도 루브릭도 산출물도 없고, 대시보드에 안 올라간다.

## 7. 말소리 절반 — 어디까지 되고 무엇이 남나

카드는 "말소리와 음악"을 요구했고 324는 음악 절반만 했다. 나머지 절반이 왜 아직
안 되는지, 정확히 어디가 막히는지 적는다.

### 지켜야 하는 선

* **녹음된 개인정보를 쓰지 않는다.** 실제 사람의 목소리를 복제하지 않는다.
* 오디오는 **코드로 만들거나 라이선스가 분명한 비개인 자료**여야 한다.
* 바이트 해시가 **고정**되어야 한다. 실행마다 달라지면 아무것도 못 잰다.
* 오디오 파일은 저장소에 안 넣는다. 실행 산출물로만 남긴다(이건 허용된다).

### 두 층으로 갈린다

**1층 — 말소리 *구조*. 지금 도구로 만들 수 있다.**

채점기의 실제 오디오 문항 상당수는 낱말을 알아들을 필요가 없다. 목소리가 있는가,
몇 사람인가, 몇 번 말하는가, 중간에 끊기는가, 찌그러졌는가. 이건 전부
**성대 진동을 흉내 낸 신호 + 포먼트 필터**로 만들 수 있고, 정답이 산수로 정해진다.
`wave`와 `math`만 쓰면 되고 해시도 고정된다. 324의 계약(원장·실험·해시)에
그대로 얹힌다.

**2층 — 낱말 알아듣기. 여기서 막힌다.**

`wave`와 `math`로 만든 소리가 사람 귀에 "one two three"로 들리는지를
**우리가 확인할 방법이 없다.** 판정자가 "말소리 없음"이라고 답했을 때 그게
판정자가 못 들은 건지 우리 합성이 말이 아니었던 건지 갈리지 않는다.
**정답이 흔들리는 시험은 시험이 아니다.**

이걸 푸는 길은 하나 있다. **오프라인 포먼트 TTS 바이너리**(예: `espeak-ng`)는
사람 녹음이 아니라 규칙으로 소리를 만들고, 화면 낭독기에서 실제로 쓰이므로
알아들을 수 있다는 것이 바깥에서 이미 서 있다. 개인 목소리 복제도 아니다.
다만 **바이트 고정**이 걸린다. 러너가 그때그때 설치하는 패키지는 판이 바뀌면
출력이 바뀔 수 있다. 그래서 쓰려면 **패키지를 버전과 sha256으로 못 박고 받는
단계**가 먼저 필요하다.

### 이번에 안 하는 이유

기술적으로 막혀서가 아니다. **이번에 승인된 실험이 원인 분리이기 때문이다.**
같은 실행에 말소리 코퍼스를 얹으면 프롬프트와 코퍼스가 **동시에** 바뀐다.
324가 겪은 혼동을 한 번 더 만드는 셈이다. 그래서 순서는 이렇다.

1. 프롬프트 A/B로 원인을 가른다 ← **지금**
2. 1층(말소리 구조) 코퍼스를 붙여 같은 방식으로 잰다
3. 2층이 필요하면 TTS 바이너리를 해시로 못 박는 단계를 먼저 만든다

**남은 사유는 한 줄로 이것이다: 낱말 알아듣기는 정답의 외부 근거가 아직 없고,
그걸 세우려면 바이트가 고정된 TTS 바이너리를 먼저 박아야 한다.**

cd batch-runner

Actions → Audio Accuracy Probe → Run workflow
  dry_run       = false
  paid_approval = true
  repeats       = 3
