# 339 — 그 한 문장은 아무것도 안 바꿨다

**한 문장으로:** [`337`](./337-format-safe-observation-pilot.md)이 등록한 10회짜리
사전시험을 **샀다.** 후보 머리말은 5번 중 **1번**만 읽을 수 있는 JSON을
돌려줬다. 통과 기준은 **5/5**였다. 그래서
[`338`](./338-format-safe-observation-ab.md)의 120회는 **안 산다.**

---

## 0. 결정

| | 기준 (§5, 실행 전에 못 박음) | 나온 값 | |
|---|---|---|---|
| **observation** (후보) | 읽을 수 있는 JSON **5/5** | **1/5** | ❌ |
| **production** (대조) | 읽을 수 있는 JSON **4/5 이상** | **5/5** | ✅ |

**대조가 통과했다는 게 중요하다.** 그건 이 실행에서 배포·경로·오디오가 다
정상이었다는 뜻이다. 즉 이건 *"측정이 안 됐다"*가 아니라
**"측정됐고, 후보가 못 넘었다"**이다.

`337` §1의 표가 이 경우에 무엇을 할지 미리 정해 놨다 — **본 비교로 안
넘어간다.** 그래서 안 넘어간다. 기준을 낮추지도, 다시 돌리지도 않는다.

## 2. 형식 — 무엇이 돌아왔나

갈래마다 5번씩, 같은 소리에 같은 문항을 물었다.

| 문항 | production | observation |
|---|---|---|
| `crate_seventeen` | JSON, `fail` | **못 읽음** |
| `shelf_fifty` | JSON, `fail` | **못 읽음** |
| `dial_left` | JSON, `fail` | **못 읽음** |
| `column_third` | JSON, `fail` | JSON, **"못 하겠다"** |
| `lamp_off` | JSON, `fail` | **못 읽음** |

### "읽힌 1개"와 "쓸 수 있는 0개"는 다른 말이다

`column_third`의 답장은 **JSON으로 읽혔다.** 다섯 키가 다 있었고 값도 계약
안의 값이었다. 그런데 그 판정이 *"판단하지 않겠다"*였다.

| | 뜻 | 몇 개 |
|---|---|---|
| `format_error:unparseable_json` | 봉투가 안 왔다 — JSON이 아니었다 | **4** |
| `sub_judge_declined` | 봉투는 왔다. 안에 "못 하겠다"가 들어 있었다 | **1** |
| 읽을 수 있는 JSON | 위 둘의 합 중 뒤엣것 | **1 / 5** |
| 쓸 수 있는 판정 | 참/거짓을 답한 것 | **0 / 5** |

`337` §5가 센 것은 **"읽을 수 있는 JSON"**이므로 **1/5**가 §5에 대는 숫자다.
5/5가 기준이었으니 1이든 0이든 미통과지만, 문서가 센 숫자와 다른 숫자를 적어
두면 나중에 둘을 구분할 방법이 없다. **1/5로 적는다.**

> 이 구분은 눈으로 한 게 아니다. `core/perception/audio.py`에서
> `sub_judge_declined`는 **JSON을 파싱하고 다섯 키를 검사한 다음에야** 붙는
> 표시다. 봉투가 안 열렸으면 그 자리까지 못 간다.

## 3. 후보 문장은 **실제로 나갔다**

갈래가 실패하면 제일 먼저 의심할 것은 *"그 문장이 안 보내진 것 아니냐"*다.
그건 아니다.

각 호출이 보낸 프롬프트 글자 수를 짝지어 빼면:

| | 관찰 − 운영 |
|---|---|
| `334`의 60쌍 | **전부 정확히 739자** |
| 이번 5쌍 | **전부 정확히 898자** |
| 차이 | **159자** = 후보 문장 158자 + 앞 공백 1자 |

다섯 쌍이 다 898이다. 하나도 안 빠졌다. 산출물에는 프롬프트 **해시**만 남고
본문은 안 남기지만, 길이만으로도 이건 확정된다 — 159자가 안 들어간 요청은
889이 아니라 739가 나온다.

산출물이 적은 머리말 이름도 `SPEECH_OBSERVATION_HEADER_V2`,
해시도 `93239fe7…`로 `337` §2와 같다.

**그러니 "안 보내서 실패했다"는 아니다. 보내고 실패했다.**

## 4. 소리도 실제로 나갔다

| | |
|---|---|
| 오디오를 실은 요청 | **10 / 10** |
| 클립당 서로 다른 digest | 전부 1개 — 중간에 파일이 바뀐 클립 없음 |
| 못 박은 길이와 어긋난 클립 | 0개 |
| 보낸 형식 | `wav`, 16,000 Hz, 모노 — `330`이 못 박은 그대로 |
| 응답이 밝힌 모델 | `gpt-audio-1.5` (10/10) |
| 오디오 토큰 | 호출당 30~34, 합 **320** |

**두 갈래가 같은 바이트를 받았다.** 클립 5개의 digest가 갈래를 가로질러
하나씩이니, 관찰 갈래가 다른 소리를 듣고 실패한 게 아니다.

> 산출물에 `prompt_token_vs_clip_seconds.pearson_r = 0.02`가 찍혀 있는데,
> **이 실행에서 그 수치는 아무 뜻도 없다.** 클립 5개 길이가 3.02초에서
> 3.44초 사이로 거의 같아서 상관을 잴 변화 폭 자체가 없다. 소리가 갔다는
> 근거는 이 상관계수가 아니라 위 표의 오디오 토큰과 digest다.

## 5. 실패 **모양**이 `334`와 같다

`335`가 산 진단은 이랬다 — 모델이 JSON을 만들다 만 게 아니라 **아예 안
만들었다.** 중괄호 0개, 첫 글자 `I`, `finish_reason: stop`, 짧은 산문.

이번 4건의 출력 길이가 그 모양과 같은 자리에 있다.

| | 출력 토큰 |
|---|---|
| `334`의 못 읽은 51건 | 18 ~ 68 (중앙값 32) |
| 이번 못 읽은 4건 | 22, 23, 24, 29 |
| 이번 읽힌 1건 (`column_third`) | 73 |
| 이번 운영 갈래 5건 | 71 ~ 87 |

JSON 봉투 하나를 채우려면 70토큰쯤 든다. 20토큰대는 **한두 문장**이다.

**여기서 멈춘다.** 이 실행은 응답 본문을 저장하지 않는다(그건 `337` §3이
정한 것이고, 받아쓰기를 `reasoning` 필드로 보내는 설계상 본문에는 소리
내용이 들어간다). 그러니 이건 **길이가 같은 자리에 있다**까지이고,
*"글자까지 같은 실패다"*는 아니다. 그걸 확인하려면 `335` 같은 진단을 또
사야 한다.

## 6. 내용 정확도 — **기록만 한다**

`337` §6이 실행 전에 정해 놨다: *"내용 정확도는 보고서에 찍히지만 어떤
결론에도 안 쓴다."* 그대로 한다. 아래는 **기록**이지 결과가 아니다.

운영 갈래 5개 (관찰 갈래는 판정이 0개라 잴 것이 없다):

| | |
|---|---|
| 맞힌 것 | **2 / 5** |
| 참인 주장 3개 | **0개 정답** — 셋 다 `fail` |
| 거짓인 주장 2개 | **2개 정답** — 둘 다 `fail` |
| 다섯 판정 | **전부 `fail`** |
| 변별력 `discrimination_j` | **0.0** |
| 사전등록 이항검정 | `p = 0.8125` |
| 이 크기에서 나올 수 있는 최소 p | **0.03125** |

**읽는 법.** 다섯 번 다 `fail`이라고 답하면 거짓 2개는 저절로 맞는다. 그게
`2/5`다. 즉 이 5개에서 채점기는 **듣고 맞힌 게 아니라 전부 아니라고 했고**,
그 결과가 우연히 40%가 됐다. `J = 0`이 그 말이다.

**그리고 이건 결론이 아니다.** 5개짜리 표본에서는 다 맞혀도 `p = 0.03125`가
최선이라, 이 크기로는 **어떤 결과가 나와도 유의하지 않다.** `331`이 51건으로
본 것과 방향은 같지만, 이 5건으로 그걸 다시 주장하지 않는다.

### 한 가지만 적어 둔다 — 사례 하나

`crate_seventeen`(참인 주장)에서 운영 갈래가 남긴 근거는 이랬다.

> The speaker says 'The blue crate holds seventeen bowls' without stating
> the quantity of seventeen explicitly.

**받아썼다. "seventeen"이라고 적어 놓고 `fail`이라고 답했다.** 못 들은 게
아니라 **판정에서 틀렸다.** `331`이 남긴 질문 — 참인 주장에 왜 이렇게
약한가 — 이 여기 다시 나온다.

**한 건이다. 여기서 아무 결론도 안 낸다.** 다음에 그 질문을 사려면 그건
따로 등록해야 한다.

## 9. 이 실행이 못 말하는 것

* **왜 안 됐는지 모른다.** 실패 *모양*이 `334`와 같은 자리라는 것까지다.
  본문을 안 저장했으므로 무엇을 썼는지는 안 봤다.
* **후보 문장이 원인인지도 모른다.** V1을 이번에 같이 안 돌렸다. 이번에
  아는 건 *"V2도 형식을 안 지켰다"*이고, *"그 문장이 도움이 안 됐다"*는
  아니다. 도움이 안 됐는지 보려면 세 갈래가 필요하다(`337` §8).
* **비율이 아니다.** 5개는 실패율의 표본이 아니다. `334`의 15%가 이번에
  20%(1/5)로 보이지만, 이 크기에서 두 수를 비교하는 건 의미가 없다.
* **다른 소리에서 어떨지 모른다.** eSpeak 합성음 `en-us` 하나, 3초 남짓,
  잡음·억양·화자 겹침 없음. 사람 목소리가 아니다.
* **모델이 시킨 대로 받아썼는지 모른다.** `reasoning` 내용을 저장 안 한다.
* **재시도가 정말 없었는지는 모른다.** 호출 기록은 10건 다
  `api_call_count = 1`이고 실행 로그에 429·5xx·타임아웃 흔적이 없다.
  하지만 SDK 안쪽 재시도는 이 계수기 아래층이라(`337` §2)
  **"재시도를 시사하는 흔적이 없다"**까지가 정확한 말이다.

## 10. 채점기 지문이 또 움직였다

| | |
|---|---|
| 이 실행이 돈 지문 | `6970a67c…` |
| 지금 `main`이 계산하는 지문 | `50f6f8bb…` |
| 언제 | A의 `#455`(`843cd533`)가 09:50:53Z 병합 — **유료 job이 끝난 09:48:12Z에서 2분 41초 뒤** |

**실행에는 영향이 없다.** 유료 구간 내내 `main`은 `e7a820e2`였고, 측정기가
실행 시점에 지문을 다시 계산해 `337` §2와 대조한 뒤 호출했다. 2분 41초는
좁지만 겹치지 않았다.

**대신 두 가지가 따라온다.**

1. `337` §2의 값은 이제 **역사**다. 안 고친다. 대신 그 값이 유료 산출물이
   적은 값과 같은지를 테스트가 검사한다 — *"이 체크아웃과 같은가"*는 실행
   전의 질문이었고, 실행 후의 질문이 아니다.
2. `338` §2의 값은 **낡았고, 다시 안 못 박는다.** 그 문서는 닫혔다.
   되살리려면 새 사전등록이 필요하고, 그때 새로 못 박는다.

## 11. 그래서 `334` §10의 4번은

**안 끝났다.** 원래 질문 — *같은 소리·같은 문항에서 지시문만 바꾸면 판정이
달라지는가* — 은 여전히 답이 없다.

지금까지 산 것:

| | 무엇을 샀나 | 무엇을 알았나 |
|---|---|---|
| `334` | 120회 | 관찰 갈래가 형식을 깼다. 판정 차이는 못 쟀다 |
| `335` | 7회 (상한 8회, 예비 1회 안 씀) | JSON을 만들다 만 게 아니라 **안 만들었다** |
| `337` | 10회 | 한 문장을 더해도 **거의 안 만든다** — 못 읽은 게 4건, 읽히긴 했는데 판정을 거절한 게 1건. 쓸 수 있는 판정은 **0건** |

> `335`의 `7회`는 이 표를 고친 값이다. 처음 쓸 때 상한 `8회`를 지출로
> 적었는데, 원본
> [`335-audio-format-diagnostic.json`](./335-audio-format-diagnostic.json)은
> `max_model_requests: 8` · `requests_planned: 7` ·
> `requests_reserved_for_transport_retry: 1` · `requests_used: 7` ·
> `requests_remaining: 1`이고,
> [`335-why-the-format-failed.md`](./335-why-the-format-failed.md) §11
> 「실행 기록」도 *"요청 7회 / 상한 8회, 예비 1회 안 썼다"*라고 적는다. 산
> 것은 7회다. 상한은 지출이 아니다.
>
> `337`의 `10회`는 그대로다. 고친 것은 **무엇을 알았나** 쪽이다. 원본
> [`337-audio-accuracy-measured.json`](./337-audio-accuracy-measured.json)의
> 10건 중 5건은 답했고, 못 답한 5건의 내역이 `judge_error`로 갈린다 —
> `format_error:unparseable_json` 4건(JSON 자체를 못 읽었다)과
> `sub_judge_declined` 1건(JSON은 읽혔고, 그 안에서 모델이 판정을
> 거절했다). **읽을 수 있는 JSON 1건과 쓸 수 있는 판정 0건은 다른
> 말이다.** 앞의 문장은 그 1건을 지우고 있었다.
>
> 두 줄 다 요약의 오기만 고쳤다. `334`·`335`·`337`이 실제로 잰 숫자는
