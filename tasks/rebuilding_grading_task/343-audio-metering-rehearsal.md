# 343 — 예행은 끝까지 갔다 (그리고 아직 아무것도 안 샀다)

**상태: 무료 예행 결과 + 유료 실행 안내.**
여기 있는 숫자는 **전부 로컬 stub의 것**이다. `gpt-audio-1.5`는 이 문서를
만드는 동안 **한 번도 안 불렸고**, 원장에도 청구서에도 한 줄 안 생겼다.

[`340`](./340-we-have-not-seen-audio-metering.md)이 "`337`이 산 소리 호출
열 건이 공통 원장에 한 줄도 안 남겼다"를 찾았고,
[`342`](./342-audio-cost-metering-prereg.md)가 그걸 고친 다음 확인할 2회짜리
시험을 등록했다. 이 문서는 **그 시험을 모델 없이 끝까지 돌린 결과**다.

**한 문장으로:** 예약 → 사용량 → 과제별 원장 → 가격 조회 → 영수증 → 보고서 →
검사기까지 **경로가 끊긴 데 없이 이어진다.** 그리고 이 문장은
**`gpt-audio-1.5`에 대해 아무것도 안 말한다** — 부른 적이 없으니까.

---

## 1. 무엇을 돌렸나

`342` §2에 등록한 것과 **같은 문**으로 들어가서 같은 코드를 지난다.
다른 건 두 가지뿐이다.

| | 예행 | 유료 실행 |
|---|---|---|
| 클라이언트 | 로컬 stub | Azure OpenAI |
| 말뭉치 | 시험이 만든 **합성 음(tone) 2개** | `330`의 eSpeak 클립 |
| 문항 · 반복 · 갈래 | 2 · 1 · 1 | **같음** |
| 요청 상한 · 벽시계 | 6 · 10분 | **같음** |
| SDK 재시도 · 실패 예산 | 0 · 1 | **같음** |
| 계량기 위치 | `WireClient` 안쪽 | **같음** |
| 검사기 | `verify_audio_metering_run.py` | **같음** |

**말뭉치가 왜 합성인가.** `330`의 클립은 CI 산출물이고 저장소에 없다. 이
기계에는 `espeak`도 없다. 그리고 **다른 버전 eSpeak으로 다시 만든 클립은
`load_speech_corpus`가 거절하는 게 맞다** — 그러라고 있는 검사다. 그래서
시험이 자기 말뭉치(음 2개)와 자기 매니페스트, 자기 예행 문서를 만들어 쓴다.
**`342`의 진짜 문서는 `330`의 매니페스트에 못 박힌 채 그대로다.**

**돌리는 법:**

```bash
cd batch-runner
python -m pytest tests/test_the_metering_run_goes_end_to_end.py -q
```

네트워크도 자격증명도 안 쓴다. 클립·매니페스트·예행 문서는 시험이 임시
디렉터리에 만들고 끝나면 사라진다. 저장소에 남는 합성 말뭉치는 **없다** —
남겨 두면 언젠가 진짜 말뭉치로 오해받는다.

## 3. 일부러 깨 보고 확인한 것

통과만 해 본 경로는 못 실패하는 경로와 구분이 안 된다. 그래서 예행이
지나는 자리마다 **틀린 입력을 넣고 거절하는지** 본다. 시험 38개
(`test_the_metering_check_can_fail.py` 19 + `test_the_metering_run_goes_end_to_end.py` 19).

### 3.1 판정이 깨져도 비용 행은 안 지워진다 — 이게 제일 중요하다

`337`의 답변은 대부분 파싱이 안 됐다. **파싱 뒤에 정산하는 계량 경로였다면
바로 그 호출들, 즉 돈이 나간 호출들을 잃는다.**

stub을 일부러 망가뜨려 두 가지를 만든다: **읽을 수 없는 답**
(`format_error:…`)과 **판정 거절**(`sub_judge_declined`). 둘은 코드에서
서로 다른 갈래를 탄다 — 앞은 봉투 파서에서 예외로 튀어나오고, 뒤는 정상
반환된다.

결과:

* 측정 스크립트는 **`exit 2`** — "아무 문항도 판정을 못 받았다". 맞는 값이다.
  **정확도** 질문이 답을 못 받은 것이다.
* 원장 행은 **2개 그대로**, 영수증도 그대로 닫힌다.
* 검사기는 **`rehearsal_ok`**, 조건 7 통과.

**두 종료 코드가 두 질문을 갈라 놓는다.** 측정 스크립트의 `2`는 "못
들었다"이고, 검사기의 `0`은 "쓴 건 기록했다"다. 한쪽이 다른 쪽을 못 덮는다.

### 3.2 상한에 닿아도 쓴 건 남는다

천장을 1로 조여서 두 번째 요청이 걸리게 만든다. 실행은 `exit 3`으로 멈추고,
**이미 나간 첫 요청은 원장에 남는다**(행 1개). 내보내기가 `finally`에서
일어나기 때문이다. 성공할 때만 내보내면 **아무도 계획 안 한 지출의 기록만
골라서 지우는 셈**이 된다.

### 3.3 거절하는 자리들

| 넣은 것 | 결과 |
|---|---|
| 다른 진단을 등록한 문서 | `exit 3` |
| 문항 1개짜리 문서 | `exit 3` — "1행은 2행이 1행을 두 번 센 게 아님을 못 보인다" |
| 문항 3개짜리 문서 | `exit 3` — 셋은 둘이 안 보여 준 걸 안 보여 준다 |
| 등록된 반복(1)과 다른 `--repeats 3` | `exit 3` |
| **바꿔치기한 매니페스트** | `exit 3` |
| 움직인 가격표 | `exit 3` |
| 움직인 채점기 | `exit 3` |
| `--cost-ledger` 없이 | 실행 자체가 거절됨 |
| `--metering-run` + `--speech-prompt-ab` 동시 | 거절 |
| 계량 문서를 A/B 문에 넣기 | `exit 3` |
| 예행 원장에 유료 행 섞기 | `exit 3` |
| 계획(2)이 상한(1)을 넘김 | `exit 3`, 보고서 안 씀 |

**매니페스트 바꿔치기가 왜 별도 지문을 받는가.** 바꿔친 말뭉치는
`load_speech_corpus`의 digest 검사를 **전부 통과한다** — 검사하는 쪽과
주장하는 쪽이 같은 파일이니까. 시험은 매니페스트에 1바이트를 더한 뒤 클립은
그대로 두고 돌린다. 클립 검사는 통과하고, **문서의 매니페스트 지문이 잡는다.**

### 3.4 검사기가 실제로 "아니오"라고 말하는가

`test_the_metering_check_can_fail.py`가 잘못된 과제 귀속·중복 행·정산 누락·
부풀린 `pricing_complete`·금액 없는 행에 붙은 금액을 일부러 넣고,
**그 결함이 주장하는 바로 그 조건이** 잡는지 본다. 중복을 "요청 하나가 기록
안 됐다"로 보고하면 읽는 사람이 없는 호출을 찾으러 간다.

---

## 4. 이 예행이 **안** 보여 주는 것

* **`gpt-audio-1.5`가 소리를 받는지** — 조건 2가 `N/A`인 이유다. stub은 귀가
  없다.
* **소리 토큰이 얼마나 붙는지** — 안 붙었다. 예상치는 `330`의 관측에서 온
  추정이고 이 실행이 확인한 게 아니다.
* **`gpt-audio-1.5`의 단가** — 여전히 가격표에 없다. `null`이 나오는 게 정답.
* **채점 정확도** — 3.1의 실행은 정확도 0이면서 통과했다. 일부러 그렇다.
* **유료 실행이 통과할지** — 예행 통과는 **경로가 이어졌다**는 뜻이지
  **유료 호출이 계량됐다**는 뜻이 아니다.

## 5. 유료 실행을 어떻게 띄우나

**⚠️ 아래를 실행하면 돈이 나간다. `342` §0의 조건이 전부 채워지기 전에는
띄우지 않는다.**

### 5.1 먼저 지문을 다시 못 박는다

`342` §2의 채점기 지문과 가격표 지문은 **작업 중 체크아웃에서 계산한
잠정치**다. 병합되면 값이 움직일 수 있다 — `337` 때 `#454`가 병합되면서
`7506ce50…`이 `6970a67c…`로 움직였고 `333`·`334`·`335`가 못 박은 값이
한꺼번에 틀린 값이 됐다.

**병합된 SHA를 체크아웃한 뒤:**

```bash
cd batch-runner
python - <<'PY'
import importlib.util, sys
sys.path.insert(0, ".")
spec = importlib.util.spec_from_file_location(
    "m", "scripts/measure_audio_grading_accuracy.py")
m = importlib.util.module_from_spec(spec)
sys.modules[spec.name] = m          # 이 줄이 없으면 dataclass 정의에서 죽는다
spec.loader.exec_module(m)
from core.cost_receipts import load_receipt_price_table
print("채점기 지문 ", m.grader_source_hash(m.PINNED_CONFIG))
print("가격표 지문 ", load_receipt_price_table().sha256)
PY
```

나온 두 값을 `342` §2의 표에 **다시 적고**, §0의 해당 줄에 체크한다.
움직였으면 **무엇이 움직였는지도 적는다.** 매니페스트 지문
(`97755288e5…`)은 `330` 이후 안 바뀌었으니 그대로다 — 바뀌었다면 그건 다른
말뭉치이고, 다시 못 박는 게 아니라 멈출 일이다.

**이 문서를 만든 가지에서 돌리면 `342` §2의 두 값이 그대로 나온다.** 아직
안 움직였다는 뜻이지 **이미 못 박았다는 뜻이 아니다.** `342` §0의 두 줄은
여전히 ⬜다 — 병합된 SHA에서 다시 돌려 보기 전까지는 채울 수 없는 칸이다.

### 5.2 클립을 가져온다

`330`의 클립은 CI 산출물이다. 매니페스트를 만든 실행에서
`speech-verification-set`을 내려받아 `--speech-clips`가 그 디렉터리를
가리키게 한다. **다시 만들지 않는다** — 다른 eSpeak이 만든 클립은 측정기가
거절하고, 그 거절이 맞다.

### 5.3 띄운다

```bash
cd batch-runner
python scripts/measure_audio_grading_accuracy.py \
  --repeats 1 \
  --metering-run ../tasks/rebuilding_grading_task/342-audio-cost-metering-prereg.md \
  --speech-set  ../tasks/rebuilding_grading_task/330-speech-verification-manifest.json \
  --speech-clips <speech-verification-set를 푼 디렉터리> \
  --cost-ledger  <이 실행 전용 새 파일>.sqlite3 \
  --out          ../tasks/rebuilding_grading_task/344-audio-metering-measured.json
```

* **`--dry-run`을 빼는 것**이 유료 실행이다. 그것 말고 §1 표의 오른쪽 칸과
  다른 인자는 없다.
* **`--cost-ledger`는 필수**다. 없으면 측정기가 거절한다 — 이 실행의 산출물이
  통째로 원장이니까.
* **원장 파일은 이 실행 전용 새 파일**이어야 한다. 예행 행이 들어 있는 파일을
  주면 거절한다.
* 사이드카(`.jsonl`)는 옆에 자동으로 나온다. 검사기가 그걸 읽는다.

### 5.4 판정한다

```bash
python scripts/verify_audio_metering_run.py \
  ../tasks/rebuilding_grading_task/344-audio-metering-measured.json
```

| 나온 것 | 뜻 | 다음 |
|---|---|---|
| `measured_ok` (exit 0) | 경로가 이어졌다 | 다음 소리 진단부터 비용이 기록된다 |
| `failed` (exit 1) | 그 조건이 가리키는 자리가 아직 안 이어졌다 | **상한을 올리거나 조건을 무르게 하지 않는다.** 고치고 다시 등록한다 |
| `rehearsal_ok` (유료 실행인데) | 답 못 한 조건이 남았다 | **유료 통과로 안 읽는다.** 왜 `rehearsal`로 적혔는지부터 본다 |
| exit 2 | 보고서와 원장이 서로를 설명 못 한다 | 판정 이전 문제다 |

**측정 스크립트가 `exit 2`로 끝나도 검사기는 돌린다.** 3.1이 그 경우다 —
판정은 못 받았고 비용은 기록됐을 수 있으며, 그 둘은 다른 질문이다.

## 6. 결과를 어떻게 읽지 **않을** 것인가

* **이 문서의 숫자를 유료 결과로 안 읽는다.** 전부 stub이다.
* **예행 통과를 "이제 비용을 다 안다"로 안 읽는다.** `gpt-audio-1.5`의 단가는
  여전히 없다. 통과의 뜻은 **"안 쓴 게 아니라 얼마인지 모른다는 걸 이제
  기록한다"**이지 "얼마인지 안다"가 아니다.
* **거절 12건을 "12가지 결함을 고쳤다"로 안 읽는다.** 각각은 그 자리에서
  틀린 입력을 거절한다는 것이고, 다른 자리에 대해 아무 말도 안 한다.
* **2회를 표본으로 안 읽는다.** 경로가 이어졌는지 보는 최소 실행이다.
* **`337`·`338`의 실패 기준은 이 문서가 안 건드린다.** 120회 실험을 재개하지
  않는다.
