# 308 · 영상·압축파일을 볼 수 없는 문제 — 조사와 결정

`307-audio-smoke-result.md`의 남은 일 목록 중 **2번(시각 렌더 대상 문제 판단)** 에 대한 답이다.
결론부터: **코드를 고치지 않는다.** 이미 맞게 동작하고 있었다.

---

## 1. 무엇이 문제로 보였나

채점기가 어떤 항목을 채점하지 못하고 이렇게 남겨둔 것들이 있었다.

```
required_visual_render_target_unavailable
```

뜻은 "이 항목은 눈으로 봐야 판정할 수 있는데, 볼 수 있는 형태로 바꿀 수가 없었다"이다.
채점기는 PDF·엑셀·PPT·워드·이미지를 그림으로 바꿔서 볼 수 있다. **영상(.mp4)과 압축파일(.zip)은 목록에 없다.**

---

## 2. 실제로 몇 건인지 세어봤다

추측하지 않고 174개 유료 채점 결과에서 직접 셌다(11조각 중 10조각이 이 저장소 이력에 남아 있음).

| | 수 |
|---|---|
| 채점한 과제 | 152개 |
| 채점한 항목 | 7,326개 |
| 못 본 항목 | **9개 (0.12%)** |
| 그중 점수에서 제외된 것 | 9개 전부 |
| 그중 잘못된 점수를 받은 것 | **0개** |

9개는 두 종류로 갈린다.

**가) 영상 4개 (과제 2개)**
`e222075d` → `GreenEnergy_v1.mp4` 1건, `75401f7c` → `Goodsin Studios CG Reel 2025.mp4` 3건.
"로고", "이미지", "폰트" 같은 기준이라 진짜로 눈으로 봐야 하는 것들이다. 영상은 그림으로 바꿀 수 없으니 못 봤다.

**나) 압축파일 5개 (과제 1개)**
`7de33b48` → `screen_reader_status_message.zip`, 안에 든 것은 React 소스코드다.
기준 문장에 `render`, `layout`, `visual` 같은 단어가 들어 있어서 "눈으로 볼 항목"으로 분류됐다.
예: "ScreenReaderStatusMessage.test.tsx는 React Testing Library로 컴포넌트를 render하고 조회한다."
이건 눈으로 볼 항목이 아니다. **소스코드를 읽어야 하는 항목인데 단어만 보고 시각으로 보낸 것**이다 —
소리 문제와 정확히 같은 종류의 실수(파일이 무엇인지 묻지 않고 문장의 단어로 판단)가 네 번째로 나온 자리다.

## 3. 결정: 영상에서 화면을 뽑아내는 기능을 만들지 않는다

만들 수는 있었다. 만들지 않기로 한 이유는 네 가지다.

**첫째, 지금 틀린 점수가 하나도 없다.** 9개 전부 "못 봤음"으로 표시되고 점수 계산에서 빠졌다.
0점을 준 것이 아니라 **아예 세지 않았다.** 이건 이미 정직한 처리다.

**둘째, 화면을 뽑아도 정직해지지 않는다.** 예를 들어 이런 기준이 있다.

> "로고가 아닌 첫 내용 장면이 시작 후 7.0초 안에 나온다."

첫 장면 한 컷만 뽑으면 그건 **로고다.** 몇 컷을 고르게 뽑아도 마찬가지다.
그러면 채점기는 "못 봤다"에서 **"봤고, 틀렸다"** 로 바뀐다.
지금까지 PR #276, 소리 고침, 샘플레이트 고침이 전부 없애려던 그 실수 —
**한계를 결과물의 결함으로 바꿔 적는 것** — 을 다시 집어넣는 셈이다.

**셋째, 규칙을 넓히면 위험하다.** 지금 규칙은 "명백히 시각적인 기준은 절대 글자 채점으로 내리지 않는다"이다.
이건 `test_explicit_visual_item_fails_closed_without_render_target`으로 못 박혀 있다.
나) 5건을 구제하려고 이 규칙을 넓히면, 읽을 수 있는 `.csv`도 같은 문에 걸린다.

**넷째, 크기가 작다.** 7,326개 중 9개다. 유료 전체 재채점 직전에 채점 경로를 바꾸는 위험이
이 크기의 이득보다 크다.

## 4. 보고 화면도 이미 맞게 말하고 있었다

처음에는 "제출물이 없다(nothing_submitted)"로 잘못 분류될 거라고 봤다. **틀린 짐작이었다.**
실제 결과 파일 9개를 분류기에 그대로 넣어보니 전부 이렇게 나온다.

```
render_target_missing   ← 도구 쪽 한계
```

`nothing_submitted`(모델 잘못) 쪽이 **아니다.** 영상은 제출됐고, 채점기가 못 봤을 뿐이라고
이미 정확히 적고 있었다. 사전 점검도 못 본 파일 이름을 `unsupported_visual_paths`에 따로 적어둔다.

그래서 **글자를 고쳐 쓸 이유가 없다.** 오히려 `judge_error_breakdown.py`가 스스로 적어둔 원칙 —
"판정은 구조화된 항목으로 하고 설명 문장으로 하지 마라, 문장을 손보는 날 집계가 조용히 바뀐다" —
을 어기게 되고, 이미 못 박아둔 검사 6곳을 이유 없이 다시 써야 한다.

## 5. 남는 한계 (숨기지 않고 적어둠)

* 영상 파일은 여전히 눈으로 볼 수 없다. 해당 항목은 계속 **점수에서 제외**된다.
  전체 185개로 늘려도 이 종류는 소수일 것으로 보이며, 실제 수는 재채점 결과에서 다시 센다.
* 나)의 분류 실수(단어만 보고 시각으로 보냄)는 **진짜 결함이 맞다.**
  다만 이걸 고치려면 채점 경로 분류기를 건드려야 하고, 그건 185개 전부의 배치를 바꾼다.
  유료 재채점 직전에 같이 태울 변경이 아니다. **별도 건으로 남긴다.**
