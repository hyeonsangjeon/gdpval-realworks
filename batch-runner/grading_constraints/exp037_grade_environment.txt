# Exact versions for the paid grade job and its free dry run (grade-run.yml,
# "Install dependencies": pip install -r requirements.txt -c <this file>).
#
# Why: the Sol 220 is graded in stages (exp037, then exp039 and exp040), and
# one grader has to mean one renderer. requirements.txt and
# requirements-renderer.txt only give lower bounds, so pip installs whatever
# is newest on the day: exp035 was graded with PyMuPDF 1.28.2, exp036 and
# exp037 with 2.1, and even exp037's two chunks differed (trimesh 5.2.0, then
# 5.2.1). These are the 269 versions pip reported for exp037's final chunk
# (run 43310879444, job 131671485958, "Successfully installed ...",
# 2026-11-13, Python 3.11), so a later grade reads deliverables with the
# libraries exp037 used.
#
# Why here and not in requirements*.txt: those two files are inside the
# grader source hash (step8_grade.compute_grader_source_hash follows -r and
# -c includes) and the Sol grader seal, so changing them would give every
# later grade a different grader identity than exp037's and force a regrade
# of exp037. This file is outside that hash on purpose and inside
# GRADING_INPUT_PATHS instead, so a change to it between a grade's dispatch
# and its checkout still refuses that grade. step8 records PyMuPDF's version
# in renderer_fingerprint, and --resume refuses a chunk whose fingerprint
# differs.
#
# A constraints file only fixes the version of a package something else asks
# for; it adds no package. To move a version, change it here in a reviewed PR
# and say which grades it affects.
