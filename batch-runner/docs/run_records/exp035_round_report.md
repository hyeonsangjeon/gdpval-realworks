## 기준본과 나란히 놓을 때 — 축이 셋입니다

exp003 기준본의 57.30은 **220 분모**입니다. 과제 220개가 전부 `pct` 값을 갖고
있고 그 평균이 57.3023입니다. exp035의 52.324와 **같은 방식으로 만들어진
값**입니다. 그래서 이 둘은 나란히 놓을 수 있습니다.

다만 두 회차 사이에 **서로 다른 방향으로 기운 축이 셋** 있습니다. 한쪽만 적으면
기울기가 한 방향으로만 보입니다.

### 축 1 — 선택기 시대차 (exp035에 유리)

커밋된 57.30은 **PR #261 이전 코드**로 채점된 값입니다. 오늘 코드로 같은 입력을
돌리면 8개가 새로 판정을 받고 1개가 판정을 잃습니다. 69개 커밋을 이분 탐색한
결과 9개 전부가 **단 한 커밋**(`1f4082e3b`, PR #261)에서 갈립니다.

9개 전부 기준본에서 0점이라 하한은 안 움직입니다. 8개가 만점이면 +3.64점이므로
**오늘 규칙으로 본 exp003은 `[57.30, 60.94]`** 구간이고 57.30은 그 하한입니다.

exp035는 #261 이후 코드로 채점됐으므로 **이 축은 exp035 쪽에 유리합니다.**

### 축 2 — 형식 선택 가드 (exp003에 유리)

바로 앞 절의 8개입니다. 이 8개가 만점이면 exp035도 +3.64점이므로
**exp035는 `[52.32, 55.96]`** 구간입니다.

**이 축은 exp003 쪽에 유리합니다.**

### 두 구간이 겹치는가 — 아니오

```
exp035 구간 = [52.32, 55.96]
exp003 구간 = [57.30, 60.94]

exp035의 가장 후한 값 55.96  <  exp003의 하한 57.30
차이 = 1.34
```

양쪽 8개는 **우연히 같은 수일 뿐 서로 다른 과제, 서로 다른 규칙**이라 상쇄되지
않습니다. exp035를 가장 후하게 보고 exp003을 가장 박하게 봐도 **exp003이
1.34점 앞섭니다.**

### 축 3 — 0호출을 무엇으로 세는가 (대시보드가 뒤집혀 보이는 이유)

이것이 81.07과 57.30이 나란히 뜨는 이유입니다.

| | exp003 (`src_595c7254`) | exp035 (`src_fd0db9d9`) |
|---|--:|--:|
| 판정 호출이 0인 과제 | 21 | 78 |
| 그중 `pct`가 0 | 21 / 21 | 78 / 78 |
| 그중 **오류로 표시된 것** | **0 / 21** | **78 / 78** |
| `graded_tasks` / `error_tasks` | 220 / 0 | 142 / 78 |
| 발행된 대표값 | **57.30** | **81.07** |
| 220 분모 평균 | **57.30** | **52.32** |

**같은 상태를 두 채점기가 다르게 셉니다.** 판정자를 한 번도 안 불렀고 점수가
0인 과제를, exp003의 채점기는 "채점된 과제"로 세고 exp035의 채점기는 "오류"로
셉니다. 두 채점기는 지문이 다른 서로 다른 코드입니다.

이 때문에 exp035의 대표값은 오류 78개를 뺀 142개의 평균이 되고 exp003의
대표값은 0점 21개를 포함한 220개의 평균이 됩니다. **81.07이 커 보이는 것은 분모에서
0점을 뺐기 때문입니다.**

이 차이는 **채점기 안에 있습니다.** 대시보드의 집계 코드는 채점기가 준
`avg_score_pct`를 그대로 통과시킬 뿐 계산하지 않습니다. 색인에
`graded_tasks`, `error_tasks`, `total_tasks`가 함께 실려 있으므로 도구의 결함도
아닙니다. 인용하는 쪽이 분모를 빼먹으면 생기는 일입니다.

### 정리

**52.32와 57.30만 나란히 놓습니다.** 81.07은 142 분모 값이라 여기 끼면 안
됩니다.

**관측.** 같은 분모에서 exp035가 52.32, exp003이 57.30입니다.

**가능한 설명.** 이 회차는 220개 중 78개가 채점대에 오르지 못했고, 그 대부분이
환경 쪽 실패였습니다.

**한계.** **이 차이를 모델 성능 차이라고 주장하지 않습니다.** 축 3개 중 둘은
방향만 알고 크기를 갈라 재지 못했고, 셋째는 채점기 버전 차이입니다. 같은
조건으로 맞추려면 기준본을 다시 채점해야 하는데 하지 않았습니다.

## 채점과 발행은 어떻게 끝났는가

채점은 **조각 9개 전부 성공**했습니다. 조각은 25개씩 4개, 24개씩 5개로 합이
220이고 겹치는 과제 번호가 하나도 없습니다.

뒤따르는 **발행 검증은 9개 전부 실패**했습니다. 돈은 이미 나갔고 결과는
`origin/main`에 올라가 있는데 그 위에 빨간 표시가 붙은 상태였습니다.

조각마다 12개씩, 합쳐서 108개 검사를 직접 돌려 원인을 갈랐습니다. 셋입니다.

| 원인 | 범위 | 성격 | 처리 |
|---|---|---|---|
| 집계 단계에 Node가 없었음 | 9개 전부 | 검사 쪽 결함 | 고침 |
| 0원과 증거 없음을 구별 못 함 | 9개 전부 | 검사 쪽 결함 | 고침 |

주는 단계가 없었습니다. 여덟 개 스크립트 중 첫 번째에서 끝나서

**둘째**는 옛 검사가 "9개 과제가 공짜로 채점된 것 같다"고 지목한 것인데,
조각별로 합치면 **정확히 78개**였고 0호출 78개와 **한 개도 다르지
않았습니다.** 값이 진짜 0인 자리를 찾아 놓고 수상하다고 한 것입니다.

**셋째는 고치지 않았습니다.** 과제 3개가 오디오를 보냈고 원장에는 38건
