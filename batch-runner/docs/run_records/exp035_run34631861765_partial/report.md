**이 기록을 만들 때 반드시 알아야 하는 사정입니다.** 릴레이는 앞 구간의
**진행 상황**을 복원하지만 **원장**은 복원하지 않습니다. 그래서 이 실행의
아티팩트 안에 있는 원장은 **자기가 부른 44문제만** 담고 있습니다:

| 원장 | 담긴 문제 |
|---|---|
| 3구간 아티팩트의 원장 | 1–58번 (58문제) |
| **이 구간 아티팩트의 원장** | **59–102번 (44문제)만** |

물려받은 58문제는 이 원장에서 보면 **아무도 부른 적 없는 문제와 똑같이
보입니다.** 그걸 `no_call_made`(진짜 0)로 적으면 앞 구간이 낸 $19.1751 위에
$0.00이 찍힙니다. 그래서 이 기록은 **두 구간의 원장을 모두 넣어** 만들었고,
`outcomes.json`에 `absent_from_supplied_ledgers` 줄은 **0개**입니다. 원장을
하나만 넣으면 그 58줄이 금액 `null`로 남고 스크립트가 `NOT PRICED` 경고를
찍습니다. 관련 고정 시험은
`tests/test_a_resumed_leg_may_not_price_inherited_work_as_free.py`입니다.

### 확정된 하한과 미확정을 갈라서

| | 계보 B 전체 | 근거 |
|---|---|---|
| **확정된 하한** | **$41.7784** | 측정된 156건을 저장소의 단가표·가격 함수로 계산 |
| **미확정** | 호출 **14건** | 원장에 예약만 남아 토큰을 모름 — `0`도 아니고 금액도 모름 |
| **계산 불가 문제** | **2개** (20·44번) | 측정된 호출이 하나도 없어 금액 `null` |
| **진짜 0** | 118문제 | 호출 자체가 없었음 |

`derived_cost_basis` 칸이 문제마다 이 넷 중 어디인지 적고 있습니다:

| 값 | 문제 수 | 뜻 |
|---|---|---|
| `all_calls_measured` | 90 | 모든 호출이 측정됨 — 계산값이 이 문제의 전액 |
| `floor_unmeasured_sends_excluded` | 10 | 측정 안 된 발신이 섞임 — **하한** |
| `no_measured_call` | 2 | 측정된 호출이 없음 — 금액 `null` |
| `no_call_made` | 118 | 호출 자체가 없었음 — 진짜 `0` |
| `absent_from_supplied_ledgers` | **0** | 원장을 다 넣었으므로 없음 |

**이건 청구서가 아닙니다.** 제공자가 실제로 청구한 금액은 여기서 확인할 수
없습니다(로컬 계정이 그 구독을 보지 못합니다). 그리고 **채점 비용과는 아무
관계가 없습니다** — 이 숫자는 220문제를 *푸는 데* 쓴 모델 호출만 담습니다.

**이 계보의 토큰 총량은 진도의 척도가 아닙니다.**

## 회차 전체 — 중복 없는 집계

이 회차에는 계보가 둘 있고, 220문제 목록은 **id도 순서도 완전히 같습니다.**
계보 A가 손댄 45문제는 계보 B가 손댄 102문제에 **전부 포함**됩니다.

세 원장을 `derive_run_cost.derive()`에 **한 번에** 넣으면 중복 없는 집계가
그대로 나옵니다. 따로 계산해서 손으로 더할 필요가 없습니다.

| 넣은 원장 | 호출 | 금액 | 호출이 있었던 문제 |
|---|---|---|---|
| 계보 A (0구간) | 88 | $14.3866 | 45 |
| 계보 B 3구간 | 96 | $19.1751 | 58 |
| 계보 B 이 구간 | 74 | $22.6033 | 44 |
| **계보 B 합** | **170** | **$41.7784** | **102** |
| **회차 전체 (A+B)** | **258** | **$56.1650** | **102** |

문제 수는 102로 **합쳐지고**(45+102 = 147이 아닙니다), 금액은 **더해집니다**.

| | 금액 | 무엇을 샀나 |
|---|---|---|
| 커버리지를 만든 지출 (계보 B) | **$41.7784** | 살아남은 102문제의 기록 |
| 다시 푸느라 버려진 지출 (계보 A) | **$14.3866** | 계보 B가 같은 45문제를 다시 풀어 대체됨 |
| **회차 합계** | **$56.1650** | 진도 **102/220 (46.4%)** |

**돈은 중복을 지우지 않습니다.** 45문제를 두 번 풀었으면 두 번 냈습니다.
중복 제거가 줄이는 것은 **문제 커버리지**이지 금액이 아닙니다.

다만 계보 A의 $14.3866이 통째로 버려진 것은 아닙니다. 그 45문제의 결과가
있어야만 3구간 기록의 반복 변동성을 잴 수 있고, 그건 이 회차의 다른 어떤
자료로도 얻을 수 없습니다.

이 구간이 새로 닿은 44문제 중 31개가 성공했고, 새 성공 1개당 $0.7291입니다.
3구간의 같은 값은 $0.4713이었습니다.

## 숫자를 어떻게 확인했나

이 기록은 손으로 만들지 않았습니다.
`batch-runner/scripts/build_partial_run_record.py`가 아티팩트에서 생성합니다.

```
python scripts/build_partial_run_record.py \
    /tmp/relay/34631861765/artifact/batch-results-34631861765 \
    --run-id 34631861765 \
    --output-dir docs/run_records/exp035_run34631861765_partial \
    --log /tmp/relay/leg3_job.clean.log \
    --log /tmp/relay/34631861765/job.log \
    --ledger /tmp/relay/34603033098/workspace/cost_ledger_condition_a.sqlite3
```

`--ledger`가 없으면 물려받은 58문제가 금액 없이 남고 스크립트가 `NOT PRICED`
경고를 찍습니다. `--log`는 **두 구간 것을 모두** 넣어야 합니다 — 실패 28개 중
15개의 제공자 문구는 3구간 로그에만 있고, 나머지 13개는 이 구간 로그에만
있습니다. 한 구간 것만 넣으면 나머지 15줄은 문구 없이 남고, 그 줄에
`message_source: "not_available"`이 붙습니다 — **제공자가 할 말이 없었던
실패가 아니라 이 기록이 설명하지 못하는 실패**라는 표시입니다. 두 가지
모두 고정 시험이 있습니다:
`tests/test_a_failure_with_no_sentence_says_so_on_its_own_row.py`와
`tests/test_a_resumed_leg_may_not_price_inherited_work_as_free.py`.
이 기록에는 `not_available`이 붙은 줄이 **0개**이고, 실패 28개가 **전부**
제공자 문구를 갖고 있습니다.

숫자는 서로 독립된 출처에서 따로 세어 맞췄습니다:

| 출처 | 무엇을 말해주나 |
|---|---|
| 실행 로그 (두 구간) | 문제별 재시도 사다리와 결말, 제공자 문구 |
| 원장 `cost_calls` (sqlite, 96 + 74행) | 호출 수, 토큰, 재시도 분류, 정산 여부 |
| 체크포인트 `step2_inference_progress_condition_a.json` | 220개 전부의 최종 상태 |
| 아티팩트 파일 시스템 | 실제로 남은 결과물 269개 |
| 문제별 영수증 `problem_solving_cost` | 비용 집계 상태 |
| 실행 단계 상태 (Actions API) | 이어받기가 실제로 일어났는지 |

맞아떨어진 것:

- 체크포인트 성공 **74개** = 결과물 폴더 **74개**
- 파일 없는 성공 0개, 파일 남긴 실패 0개
- 원장 170행 = 문제별 `calls` 합계 170
- 물려받은 58문제의 성공·실패·파일·금액이 3구간 기록과 **전부 동일**
- 3구간 원장의 문제 58개 ∪ 이 구간 원장의 문제 44개 = 시도한 102개
- 이 구간 원장의 44문제 = 이 구간이 **새로** 푼 44문제와 정확히 일치
- 사다리에서 센 요금 거절 문제 31개 ⊇ 최종 기록 `rate_limit` 15개
- $19.1751 + $22.6033 = $41.7784, $14.3866 + $41.7784 = $56.1650

## 이 폴더의 파일

- `report.md` — 이 문서
- `outcomes.json` — **220문제 전부**의 문제별 기록. 시도한 102개는 상세히,
  시작 못 한 118개는 `never_started`로.
- `deliverable_manifest.json` — 74문제가 남긴 269개 파일의 이름·크기·sha256

`outcomes.json`의 비용 칸은 **두 종류**이고 절대 섞으면 안 됩니다:

| 칸 | 뜻 |
|---|---|
| `model_cost_usd` | **실행 자신이** 호출을 종결하며 매긴 금액. 102개 전부 `null` |
| `derived_cost_usd_from_measured_tokens` | 그 토큰을 **나중에 밖에서** 다시 계산한 값 |
| `derived_cost_is_provider_billed` | 전부 `false` |

둘 다 청구서가 아니고, 둘 다 채점 비용과 무관합니다.

## 왜 `results/`가 아니라 여기에 있나

`batch-runner/results/` 아래는 **대시보드에 발행되는 실험** 자리입니다. 중단된
실행을 거기 두면 발행에 필요한 `report_data.json`이 없어 빌드가 서고, 억지로
만들어 넣으면 이 실행이 리더보드에 점수처럼 올라갑니다. 자세한 근거는
`../README.md`에 적었습니다.
