# 오디오 사용량 파생 복구본 v1

발행된 영수증이 담을 필드가 없어서 적지 못한 오디오 토큰을, 그 영수증 자신의
원장에서 다시 읽어 **별도 파일로** 적어 둔 것입니다.

이 디렉터리의 어떤 파일도 채점 결과가 아닙니다. 원본 채점 파일은 그대로 있고,
점수·판정·과제 결과의 권위는 계속 원본에 있습니다.

작성 시점: 2026-09-13. 기준 커밋: `97ac294`.

---

## 1. 왜 필요한가

exp035 채점 회차의 조각 2와 조각 8은 오디오 지각 호출을 냈습니다. 그 호출의
토큰 수는 원장(`*.cost_ledger.jsonl`)에 줄 단위로 남아 있습니다. 그런데 당시의
영수증 계약 `cost-receipt-v1`에는 오디오 토큰을 적을 자리가 없었습니다. 그래서
영수증은 그 수치에 대해 **아무 말도 하지 않은 채** 발행됐고, 검증기는 "원장이
영수증이 표현할 수 없는 토큰 종류를 담고 있다"(`usage_containment`)로 실패를
냈습니다.

계약에 필드를 더하는 것으로 **앞으로 쓰일 영수증**은 고쳐집니다. 그러나 이미
발행된 두 영수증은 몇 달 전에 쓰인 불변 증거입니다. 스키마가 숫자를 받아준다고
해서 이미 발행된 파일에 숫자가 생기지는 않습니다.

그래서 두 갈래로 나눴습니다.

- **계약과 직렬화기**: 오디오 필드를 명시적 선택 필드로 정의해 앞으로의 영수증이
  이 값을 싣도록 고쳤습니다. (이 저장소의 소스 변경분)
- **이미 발행된 두 건**: 원본을 고치지 않고, 원장에서 유도한 값을 출처·변환
  해시와 함께 여기에 따로 발행합니다. (이 디렉터리)

## 2. 이것이 주장하는 것과 주장하지 않는 것

**주장합니다.** 조각 2와 조각 8의 원장에는 오디오 입력 토큰이 각각 8,999개와
2,400개, 합계 11,399개 기록되어 있습니다. 이를 낸 호출은 각각 30건과 8건,
합계 38건입니다. 이 값은 `gpt-audio-1.5` 배포 앞으로 정산된(`settled`) 줄에서만
나옵니다.

**주장하지 않습니다.**

- 이 파생본이 원본 채점 파일을 대체한다고 주장하지 않습니다.
- 재채점이 아닙니다. 점수·판정자 결정·과제 성패는 읽지도 옮기지도 않았습니다.
- 두 회차가 이제 완전(complete)해졌다고 주장하지 않습니다. 두 회차의 영수증
  상태는 여전히 `partial`이고 `estimated_cost_usd`는 여전히 `null`입니다.
  해당 모델의 가격이 발행된 적이 없기 때문이고, 이 유도는 가격을 만들어내지
  않습니다.
- 금액을 한 푼도 싣지 않습니다. 이 디렉터리에는 비용 수치가 없습니다.
- 오디오 토큰을 어떤 합계에도 더하지 않습니다. 오디오는 공급자가 이미 보고한
  입력 토큰의 **일부**이므로, 더하면 같은 토큰을 두 번 계상하게 됩니다.
  `input_tokens`는 원본 그대로이고 그 안에 오디오가 이미 들어 있습니다.

## 3. null을 어떻게 읽는가

**`null`은 아무도 재지 않았다는 뜻이고, 0이 아닙니다.**

텍스트만 쓰는 호출은 오디오 열을 비운 채 원장에 들어갑니다. 조각 8의 경우
`gpt-5.6-sol` 앞으로 정산된 1,714줄이 오디오 두 열 모두 `null`이고, 실제로
값을 보고한 줄은 `gpt-audio-1.5`의 8줄뿐입니다. 이 1,714줄을 더해 `0`으로
적으면 "재보니 오디오가 없었다"가 되는데, 증거가 말하는 것은 "아무도 보지
않았다"입니다.

그래서 이 파생본에서 텍스트만 쓴 구성 요소는 `null`로 남습니다. 반면
`gpt-audio-1.5` 줄이 실제로 보고한 출력 오디오 `0`은 **측정된 0**이므로
`0`으로 적습니다. 둘은 끝까지 구별됩니다.

이 규칙은 여기서 따로 만든 것이 아닙니다. 유도 스크립트는 직렬화기의
`empty_usage()`를 그대로 불러 씨앗으로 쓰고, `build_receipt`와 같은 방식으로
`None`을 건너뜁니다. 직렬화기와 검증기가 토큰 종류 목록에 대해 어긋나면
유도는 값을 내지 않고 중단합니다.

## 4. 무엇이 움직였고 무엇이 움직이지 않았는가

수리 전 검증기와 수리 후 검증기를, 손대지 않은 같은 파일들 위에서 나란히
돌린 결과입니다.

| | |
|---|---|
| 대조한 꾸러미 | 42 |
| 판정이 그대로인 꾸러미 | 40 |
| 판정이 움직인 꾸러미 | 2 |
| 집계된 줄 수·과제 수가 움직인 꾸러미 | 0 |

움직인 2건은 조각 2와 조각 8이고, 둘 다 같은 방향입니다.

```
was: ['usage_containment']
now: ['components_reconcile', 'usage_reconciles']
```

**이것은 "통과로 바뀌었다"가 아닙니다.** 실패 하나가 실패 둘이 됐습니다.
달라진 것은 실패의 성격입니다. 전에는 "영수증이 표현할 수 없는 종류가 있다"라는,
무엇이 얼마나 빠졌는지 말할 수 없는 실패였습니다. 지금은 "영수증이 원장과
이 값에서 어긋난다"라는, 어긋난 항목을 이름과 수치로 지목하는 실패입니다.
두 영수증은 불변 증거이므로 이 어긋남 자체는 남아 있어야 하고, 남아 있는 편이
맞습니다. 그 어긋남의 내용이 이 디렉터리의 파일입니다.

나머지 40건의 판정은 한 글자도 바뀌지 않았습니다. 42건 전체에서 집계된 정산
줄 수와 과제 수도 바뀌지 않았습니다.

## 5. 인벤토리 (2026-09-13 기준)

고정된 숫자를 테스트에 박아 두는 대신, 커밋된 것을 그때그때 찾아 검사합니다.
아래는 그 시점의 실측값이며, 나중에 달라지면 고쳐야 할 테스트가 아니라
설명해야 할 사실입니다.

| | |
|---|---|
| 커밋된 원장 꾸러미 | 42 |
| 짝이 되는 채점 파일이 있는 것 | 42 |
| 정산된 호출 줄 합계 | 87,244 |
| 원장에 오디오가 기록된 꾸러미 | 2 |

세는 방법은 `git ls-files data/grades/**.cost_ledger.jsonl`입니다. 작업 트리를
훑지 않습니다. 발행됐다는 것은 커밋됐다는 뜻이고, 작업 트리에는 중단된 병합의
잔여물이 있을 수 있기 때문입니다.

`gold_smoke_audio`·`gold_audio_repeat` 계열 진단 회차는 이름과 달리 **채점**
원장에 오디오가 없습니다. 그 회차의 오디오는 추론 쪽에서 났습니다. 채점 비용
원장만 보는 이 집계에서 2건인 이유입니다.

## 6. 재현

```bash
cd batch-runner
python3 scripts/derive_audio_receipt_repair.py --check
```

`--check`는 아무것도 쓰지 않고, 디스크에 있는 파일과 지금 유도한 값을 바이트
단위로 비교해 `ok` / `MISSING` / `STALE`를 찍습니다. 출력에 시각이 들어가지
않으므로 같은 입력은 같은 바이트를 냅니다. 여기 적힌 해시를 믿는 대신 직접
돌려서 맞춰 보는 쪽이 낫습니다.

유도 스크립트 자신의 해시:

```
caeff0821345f76fabb56ad66bdf8e84d8b3b75e882029f6deb20e3f2b05c334
  batch-runner/scripts/derive_audio_receipt_repair.py
```

파생본:

```
683518e89a97e3448c12096a09455d0a7c2b210d9592979cf73e9e741b90a0fe
  exp035_codex_foundry_full220__src_fd0db9d9d78d6d54__shard-002-of-009.audio_repair.json
bad0712a3f2f85be08b42713feef44e19811159b5cfc4a7223293a426a7ab3ef
```

각 파생본 안에는 그것이 읽은 채점 파일과 원장 파일의 경로와 sha256이 들어
있습니다. 원본 채점 회차의 출처(실험 식별자, 채점기 소스 해시, 채점 시각,
판정자 설정, rubric 개정, 추론 리비전 등 17개 필드)는 원본에서 **그대로 복사**
되며, 어느 것도 다시 계산하거나 다시 서명하지 않습니다.

## 7. 유도가 거부하는 경우

이 스크립트는 오디오 두 열을 더하는 것 외의 일을 하게 되면 파일을 쓰지 않고
멈춥니다. 유도할 때마다 기존 수치를 원장에서 독립적으로 다시 계산해 원본이
말하는 값과 대조하며, 하나라도 어긋나면 `DerivationRefused`로 중단합니다.
대조 대상은 영수증 전체와 각 구성 요소 각각에 대해:

- 오디오가 아닌 네 가지 토큰 수 전부
- 호출 건수
- 발행된 구성 요소에 실제로 대응하는 원장 줄이 있는지
- 음수 토큰 수가 있는지
- 직렬화기와 검증기가 토큰 종류 목록에 합의하는지

두 파일 모두 중단 없이 유도됐습니다. 즉 **이 수리와 무관한 수치는 하나도
움직이지 않았다**는 것이, 문서의 주장이 아니라 코드의 중단 조건으로 확인된
상태입니다.

원본 증거는 손대지 않았습니다. 이 작업 내내 `git status --porcelain data/`는
비어 있습니다.

## 8. 이 수리가 닿지 않는 곳

영수증 한 건과 그 안의 각 구성 요소까지는 오디오가 실립니다. 거기서
끊깁니다.

대시보드가 회차 단위로 읽는 합계(`core/cost_projection.py`의
`summarize_cost_receipts`)에는 **어떤 토큰 종류도 실리지 않습니다.** 오디오만
빠진 것이 아니라 그 전부터 있던 입력·캐시 입력·출력·추론 네 종류도 똑같이
없습니다. 원래 그 모양이었고, 이 수리가 무언가를 빠뜨린 결과가 아닙니다.

회차 합계에 토큰 수를 넣으려면 이미 발행된 모든 보고서의 `summary.cost`
블록이 담는 내용이 바뀝니다. 영수증 계약을 고치는 일과는 다른 결정이고,
이 수리는 그 결정을 하지 않습니다. 적어 두는 이유는, 적지 않으면 나중에
읽는 사람이 이 빈자리를 보고 "오디오 작업이 한 군데를 놓쳤구나"로 읽기
때문입니다.

**채점 쪽 합계는 다릅니다.** `core/cost_receipts.py`의 `summarise_receipts`는
사용량을 싣고 있고, 씨앗으로 `empty_usage()`를 쓰기 때문에 고칠 것 없이
오디오 두 열을 그대로 물려받습니다. 이름이 거의 같은 두 함수라 헷갈리기
쉽습니다.

| | 사용량을 싣는가 |
|---|---|
| 영수증 한 건 (`project_cost_receipt`) | 예 — 이번에 고침 |
| 영수증의 구성 요소 각각 | 예 — 이번에 고침 |
| 채점 회차 합계 (`summarise_receipts`) | 예 — 자동으로 따라옴 |
| 보고서 회차 합계 (`summarize_cost_receipts`) | 아니오 — 원래부터 전 종류 없음 |

이 경계는 말로만 두지 않고 테스트로 고정했습니다.
`batch-runner/tests/test_cost_projection.py`와
`scripts/__tests__/cost-receipt.test.mjs` 양쪽에 같은 수치로 들어 있습니다.
한쪽 구현만 바뀌면 한쪽 숫자만 움직여서 드러납니다.

화면 쪽은 오늘 사용량을 아예 읽지 않습니다. 다만 TypeScript 타입이
`Record<string, number>`로 적혀 있었는데 실제로는 `null`이 올 수 있었으므로,
`Record<string, number | null>`로 고치고 "`?? 0`으로 읽지 말 것"을 주석으로
남겼습니다.
