# 비교 기준이 된 exp003 점수는 **지금과 다른 채점기**에서 나왔습니다

exp035의 점수는 결국 exp003과 비교됩니다. 그 비교 상대인 `57.3`은 저장소에
커밋돼 있고, 이 회차의 채점 설정도 그 값을 기준으로 짜여 있습니다.

**그 값은 오늘 코드로 다시 만들 수 없습니다.** 채점기 안에서 "어떤 파일을
채점할지 고르는 부분"이 그 값이 나온 뒤에 바뀌었고, 같은 입력에 대해 이제
다른 답을 냅니다. 이 문서는 얼마나 다른지, 왜 다른지, 그래서 exp035 비교를
어떻게 읽어야 하는지를 적습니다.

모델을 부르지 않았고 채점을 다시 돌리지 않았습니다. 돈이 들지 않았습니다.

---

## 한 줄로

**커밋된 exp003의 `57.3`은 오늘 규칙에서는 하한입니다.** 같은 산출물인데
오늘 코드는 8문제를 판정자에게 더 보내고 1문제를 덜 보냅니다. 9개 전부
기준본에서 0점이었으므로 하한은 그대로고, 위쪽으로만 최대 **+3.64점** 열려
있습니다. 그래서 오늘 규칙에서 exp003의 값은 **57.30 이상 60.94 이하**이고,
**exp035는 그중 유리한 쪽 규칙으로 채점되고 있습니다.**

## 먼저 용어 세 가지

이 문서에서만 쓰는 말이 아니라 저장소 코드에 있는 말입니다.

| 말 | 뜻 |
|---|---|
| **선택기** | `core/deliverable_selector.py`. 모델이 낸 파일 여러 개 중 **무엇을 채점할지 고르는** 코드입니다. 판정자(모델)가 아니라 규칙입니다 |
| **판정자** | 실제로 점수를 매기는 모델(`gpt-5.6-sol`). 선택기가 파일을 못 고르면 판정자는 **한 번도 불리지 않습니다** |
| **`wrong_format_primary`** | 선택기가 "문제가 요구한 형식의 파일이 없다"고 판단해 과제 전체를 거절한 상태. 이때 그 과제의 모든 rubric 항목이 채점 오류가 되고 **0점**이 됩니다 |

**핵심은 이겁니다.** 선택기가 거절하면 점수가 0인데, 그 0은 "모델이 못했다"가
아니라 **"아무도 안 봤다"** 입니다. 이 문서가 다루는 것은 그 0이 몇 개냐가
코드 버전에 따라 달라진다는 사실입니다.

## 1. 재구성이 정확한지부터 확인했습니다

산출물 파일 목록은 아티팩트가 아니라 **기준본 채점 결과 안에서 복원**했습니다.
복원이 부정확하면 뒤의 차이가 전부 복원 실수일 수 있습니다. 그래서 결론을
내기 전에 이것부터 검증했습니다.

**관측** — 기준본 자신의 코드 커밋 `99841e08`에서 복원한 입력을 돌린 결과:

|---|---|

| 선택 규칙이 커밋된 값과 일치 | **220 / 220** |
| 불일치 | **0** |
| 그때 집계 | `ok` 199 · `wrong_format_primary` 20 · `no_generated_candidate` 1 |

**뜻** — 복원은 정확합니다. 따라서 아래의 차이는 복원 실수가 아니라 **코드가
실제로 다르게 동작한 것**입니다.

> 이 검증 전에 복원 방식 세 가지(참조 파일 제외 목록을 넣을 때·뺄 때,
> `reference_files`를 넘길 때·안 넘길 때)를 비교해 220개 상태가 전부 같음을
> 먼저 확인했습니다. 그래도 "커밋된 값과 같은가"는 별개 질문이라 위 검증을

거절됐다는 표가 있고, 그 표의 과제 6개가 제 8개 중 6개와 같습니다 —

## 4. 판정자를 잃는 1개는 퇴보가 아니라 **교정**입니다

`ok` 개수만 보면 8 늘고 1 줄어 순증 7입니다. 줄어든 1개를 그냥 두면
"고치면서 하나를 망가뜨렸다"로 읽히므로 기전을 확인했습니다.

과제 `4b894ae3`입니다.

| | `db96c92f4` (#261 직전) | `1f4082e3b` (#261) |
|---|---|---|
| 선택기가 읽은 요구 형식 | `.aac .doc` **`.docx`** `.flac .m4a .mp3 .ogg .wav` | `.aac .flac .m4a .mp3 .ogg .wav` |
| 모델이 낸 파일 | `.docx` 2개 | 같음 |
| 결과 | `ok` → 판정자에게 감 | `wrong_format_primary` → 거절 |

**문제가 요구한 산출물은 `.WAV` 파일 하나입니다.** 지시문은 이렇게 끝납니다.

> Your final delivered file should be a Stereo mix of all the stems exported in
> 48k/24b .WAV, named "State of Affairs_FULL_EDIT_MIX" …

rubric 첫 세 항목도 전부 WAV를 검사합니다 — 이름이 정확히
`State of Affairs_FULL_EDIT_MIX.wav`인가, 압축 형식이 아닌 WAV인가,
샘플레이트가 48kHz인가.

그럼 `.docx`는 어디서 왔나. **아티스트가 준 참조 입력 파일 이름입니다.**

> The artist has provided some timecode references … in reference file attached
> (**Bass Edit Spots.docx**).

이 파일은 과제의 `reference_files`에 그대로 들어 있습니다 — 모델이 **읽으라고
준 입력**이지 내라고 한 출력이 아닙니다. 옛 코드가 그 이름의 `.docx`를 요구
형식으로 읽어, 오디오 과제에 Word 문서를 낸 것을 통과시켰던 것입니다.

**그리고 그 통과는 점수로 이어지지 않았습니다.** 기준본에서 이 과제는
판정자를 **37번** 부르고 **0.0점**을 받았습니다. 판정자가 실제로 Word
문서를 보고 0점을 준 것입니다.

**그러므로 이 1개는 옳은 방향입니다.** 오디오를 요구한 과제에 Word 문서를
낸 것을 이제 선택기가 거절합니다. 점수도 안 움직입니다(0.0 → 0.0).

## 5. #261이 "일어날 수 없다"고 적은 일이 220개 중 1번 일어났습니다

#261 본문의 「Blast radius」 절은 이렇게 적혀 있습니다.

> The change is a **restriction**: requiring whitespace in front can only make a
> pattern match less often. It cannot make the guard fire where it does not fire
> today, so **no task can be newly refused**.

**관측** — 새로 거절된 과제가 **220개 중 정확히 1개** 있습니다(§4의
`4b894ae3`).

**추론이 놓친 자리** — 앞 문장까지는 맞습니다. 이 변경은 요구 형식 집합을
**좁히기만** 합니다. 같은 절의 표도 "형식을 새로 얻은 과제 0개"라고 적고
있고 그것도 맞습니다.

문제는 그다음입니다. 선택기의 거절 조건은 이렇습니다.

```
요구 형식이 하나라도 있는데, 낸 파일 중 거기 맞는 게 하나도 없으면 → 거절
```

**집합을 좁히면 "맞던 그 하나"가 집합에서 빠질 수 있습니다.** `4b894ae3`이
정확히 그 경우입니다 — 요구 형식에서 `.docx`가 빠지자, 맞던 유일한 형식이
사라져 남은 오디오 형식들과 아무것도 안 맞게 됐고, 그래서 가드가 **새로**
발동했습니다.

**"형식을 새로 얻지 않는다"와 "새로 거절되지 않는다"는 다른 말입니다.**
#261의 표는 앞의 것을 셌고, 본문 문장은 뒤의 것을 주장했습니다.

**이 문서가 주장하지 않는 것**

- **#261이 틀린 변경이었다고 말하지 않습니다.** 결과는 옳았습니다 — 8개를
  옳게 살리고 1개를 옳게 거절했습니다.
- **지금 고쳐야 할 결함이라고 말하지 않습니다.** 이 코퍼스에서 영향은
  1개이고, 그 1개는 점수가 0.0에서 0.0으로 안 움직입니다.
- 말하는 것은 하나입니다 — **그 문장을 근거로 "재채점 없이도 옛 점수와
  비교 가능하다"고 판단하면 안 됩니다.** 실제로는 9개가 갈립니다.

## 6. 점수로는 얼마인가 — `57.3`은 하한입니다

**관측**

| | 값 |
|---|---|
| 커밋된 기준본 평균 | **57.3** — 파일의 `summary.openai_compat.avg_score_pct` |
| 과제별 `pct` 220개를 직접 평균 | **57.3023** — 위와 일치 |
| 갈리는 9개의 기준본 `pct` | **전부 0.0** |

| 가정 | 오늘 규칙에서의 값 |
|---|---|
| 새로 판정받는 8개가 **전부 0점** | **57.30** — 하한 |
| 새로 판정받는 8개가 **전부 만점** | **60.94** — 상한 |

계산은 간단합니다. 8개가 만점이면 220개 평균이 8÷220×100 = **3.64점** 오릅니다.
판정을 잃는 1개는 이미 0.0이라 하한을 안 내립니다.

**그래서 오늘 규칙에서 exp003의 값은 `[57.30, 60.94]` 구간입니다.**

**이 폭은 같은 파일이 함께 적은 신뢰구간과 비슷한 크기입니다.** 기준본은
평균 옆에 `ci_pct: 3.75`를 적고 있습니다. 이것은 220개 점수의 표준편차로 낸
평균의 95% 신뢰구간 절반이고(`1.96 × σ / √n`, `step8_grade.py:1529`),
**"과제를 다시 뽑으면 평균이 얼마나 흔들리는가"** 를 말합니다. 위의 3.64는
**같은 220개에서 채점기 코드만 바뀔 때** 열리는 폭이라 성질이 다릅니다.
**두 값을 더하거나 하나로 합치면 안 됩니다.** 다만 크기가 비슷하다는 것은,
코드 시대차가 이 비교에서 무시해도 될 만큼 작지 않다는 뜻입니다.

**한계 — 이 구간이 답이 아닙니다.**

- **8개가 점수를 잘 받았으리라고 주장하지 않습니다.** 상한 60.94는 "만점이면"
  이라는 가정의 산수이지 예측이 아닙니다. 실제 값은 판정자를 불러야 알고,
  그건 돈이 듭니다.
- **기준본을 다시 채점하지 않았습니다.** 이 문서는 판정자 호출 0회입니다.
- 하한 57.30만이 측정된 값입니다. 구간의 나머지는 **아직 측정되지 않았습니다.**

## 7. exp035 비교에 무슨 뜻인가 — 5개가 비대칭입니다

exp035는 오늘 코드(#261 이후)로 채점되고 있습니다. 커밋된 exp003 값은 #261
이전 코드에서 나왔습니다. **두 값은 이 축에서 같은 조건이 아닙니다.**

추상적으로 두지 않고, 판정자에게 새로 가게 된 8개가 exp035에서 어떤
상태인지 오늘 선택기로 직접 확인했습니다.

| 과제 | exp035 결말 | 파일 | 오늘 선택기 | rubric | 비대칭인가 |
|---|---|---|---|---|---|
| `d4525420` | ok | 1 | `ok` | 18 | **예** |
| `a0552909` | ok | 7 | `ok` | 50 | **예** |
| `1e5a1d7f` | ok | 2 | `ok` | 18 | **예** |
| `a69be28f` | ok | 9 | `ok` | 54 | **예** |
| `552b7dd0` | ok | 7 | `ok` | 63 | **예** |

| `6074bba3` | **failed** (`transport_error`) | 0 | — | 48 | 아니오 — 낸 파일이 없음 |

**관측** — **5개 과제, rubric 항목 203개**에서 exp035는 판정자에게 가고,
커밋된 exp003 값은 가지 않았습니다.

**뜻** — 이 5개에서 exp003은 **0점이 보장**돼 있고 exp035는 **0점 이상**
입니다. 두 값을 나란히 놓으면 이 축에서는 **exp035 쪽이 유리하게 기울어
있습니다.** 얼마나 기우는지는 exp035 채점이 끝나야 알 수 있습니다 — 5개가
전부 0점이면 기울지 않고, 전부 만점이면 2.27점(5÷220×100) 기웁니다.

**남은 3개는 기울지 않습니다.** 2개는 exp035가 애초에 파일을 못 냈고
(처리량 한도·연결 끊김), 1개는 exp035도 오늘 선택기에 걸립니다.

**가능한 설명이 아니라 산술입니다.** 5개가 exp035에서는 판정 대상이고
exp003의 커밋된 값에서는 아니라는 것은 두 파일을 대조해 센 값입니다.

**한계** — 이 비대칭은 **선택기 축 하나**입니다. 두 채점의 차이는 이것만이
아니고, `docs/run_records/grading_design.md`가 적은 대로 추론 쪽에서
하네스·모델·배포 세 축이 동시에 움직입니다. 이 문서는 그중 **판정자 쪽에서
하나가 더 움직이고 있었다**는 것을 더합니다.

## 8. 혼동하면 안 되는 것

**exp035의 8개와 이 문서의 8개는 다른 것입니다.** 이름이 비슷하고 개수가
같아서 겹쳐 읽기 쉽습니다.

| | 이 문서의 8개 | `report.md`의 8개 |
|---|---|---|
| 어느 실행 | exp003 (기준본) | **exp035** |
| `selection_status` | `wrong_format_primary` | `selection_error` |
| `selection_rule` | `set_diff_then_wrong_format_guard` | `format_variant_no_match` |
| 어느 가드 | 요구 형식이 하나도 안 맞음 | 형식 변형 중에서 고르지 못함 |
| 원인 | **코드 시대차** — 옛 코드와 오늘 코드가 다르게 답함 | **오늘 코드의 동작** — 시대차가 아님 |
| 무엇을 해야 하나 | 비교할 때 알고 있어야 함 | 별개 사안 |

**`selection_status`와 `selection_rule`은 다른 칸입니다.** `report.md`는 그
칸을 "선택기가 멈춘 이유"로 이름 붙이고 **규칙** 쪽을 넣었습니다. 이름만
보면 상태처럼 읽히지만 어긋난 게 아니라 다른 칸을 적은 것입니다.

**`15d37511` 한 과제만 양쪽에 다 들어 있습니다.** exp003에서는 옛 코드가
거절했고(오늘 코드면 판정받음), exp035에서는 오늘 코드가 다른 가드로
거절합니다. 같은 과제이지 같은 원인이 아닙니다.
