## 숫자를 어떻게 확인했나

이 기록은 손으로 만들지 않았습니다.
`batch-runner/scripts/build_partial_run_record.py`가 아티팩트에서 생성합니다.

```
python scripts/build_partial_run_record.py /tmp/relay/34603033098 \
    --run-id 34603033098 \
    --output-dir docs/run_records/exp035_run34603033098_partial \
    --log /tmp/relay/leg3_job.clean.log
```

이 구간은 이어받지 않았으므로 로그가 하나뿐이고 `--log`도 한 번입니다.
**이어받은 구간에서는 `--log`를 구간 수만큼 넣어야 합니다** — 한 구간은
자기가 부른 문제만 로그에 적으므로, 물려받은 실패의 제공자 문구는 그 문제를
실제로 부른 구간의 로그에만 있습니다. 빠뜨리면 그 줄은 문구 없이 남고
`message_source: "not_available"`이 붙습니다. 고정 시험은
`tests/test_a_failure_with_no_sentence_says_so_on_its_own_row.py`입니다.

같은 스크립트를 0구간 아티팩트에 돌려 **손으로 만들었던 기존 기록과
비교했습니다.** `deliverable_manifest.json`은 바이트 단위로 동일하고,
`outcomes.json`은 두 곳만 다릅니다:

| 차이 | 줄 | 성격 |
|---|---|---|
| `resolved_model`이 `null` → `"gpt-5.4"` | 10줄 (5·6·8·11·12·16·31·32·41·42) | **정정** |
| `derived_cost_*` 칸 순서 | 전 줄 | 표시 순서만 |

정정 쪽을 설명하면: 손으로 만든 기록은 문제별 `resolved_model`을 **원장의 첫
행**에서 가져왔는데, 첫 행이 종결되지 않은 예약(`reserved`)이면 모델 이름이
비어 있습니다. 그래서 같은 줄의 `deployment`가 `gpt-5.4`이고 정산된 턴이
170,555 토큰을 싣고 있는데도 모델이 `null`로 찍혔습니다. 스크립트는 **정산된
턴만** 보고 값을 정합니다. 어느 모델이 답했는가와 몇 번이 측정되지 않았는가는
다른 질문이고, 두 번째 질문에는 이미 `calls_reserved`라는 자기 칸이 있습니다.

칸 순서 쪽은 손으로 만든 파일이 시도한 줄과 미시도 줄에서 서로 다른 순서를
쓰고 있던 것이고, 스크립트는 220줄 모두 같은 순서로 씁니다. 값은 같습니다.

숫자는 서로 독립된 출처에서 따로 세어 맞췄습니다:

| 출처 | 무엇을 말해주나 |
|---|---|
| 실행 로그 | 문제별 재시도 사다리와 결말, 제공자 문구 |
| 원장 `cost_calls` (sqlite, 96행) | 턴 수, 토큰, 재시도 분류, 정산 여부 |
| 체크포인트 `step2_inference_progress_condition_a.json` | 220개 전부의 최종 상태 |
| 아티팩트 파일 시스템 | 실제로 남은 결과물 151개 |
| 문제별 영수증 `problem_solving_cost` | 비용 집계 상태 |
| 허브 `_checkpoint/lineages/*/current.json` | 계보와 세대, 결과물 수 |

맞아떨어진 것:

- 체크포인트 성공 **43개** = 결과물 폴더 **43개** = 허브 세대의 결과물 목록
- 파일 없는 성공 0개, 파일 남긴 실패 0개
- 원장 96행 = 문제별 `calls` 합계 96
- 두 구간의 220개 id 집합과 **순서**가 완전히 동일
- 사다리에서 센 요금 거절 문제 18개 ⊇ 최종 기록 `rate_limit` 7개

## 이 폴더의 파일

- `report.md` — 이 문서
- `outcomes.json` — **220문제 전부**의 문제별 기록. 시도한 58개는 상세히,
  시작 못 한 162개는 `never_started`로.
- `deliverable_manifest.json` — 43문제가 남긴 151개 파일의 이름·크기·sha256

`outcomes.json`의 비용 칸은 **두 종류**이고 절대 섞으면 안 됩니다:

| 칸 | 뜻 |
|---|---|
| `model_cost_usd` | **실행 자신이** 호출을 종결하며 매긴 금액. 58개 전부 `null` |
| `derived_cost_usd_from_measured_tokens` | 그 토큰을 **나중에 밖에서** 다시 계산한 값 |
| `derived_cost_is_provider_billed` | 전부 `false` |

둘 다 청구서가 아니고, 둘 다 채점 비용과 무관합니다.

## 왜 `results/`가 아니라 여기에 있나

`batch-runner/results/` 아래는 **대시보드에 발행되는 실험** 자리입니다. 중단된
실행을 거기 두면 발행에 필요한 `report_data.json`이 없어 빌드가 서고, 억지로
만들어 넣으면 이 실행이 리더보드에 점수처럼 올라갑니다. 자세한 근거는
`../README.md`에 적었습니다.
